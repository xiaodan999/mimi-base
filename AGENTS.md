# AGENTS.md

## What this repo is

`mimi-base` ("秘密基地") is a personal, mobile-first PWA for photos, posts and
expense records. Frontend: React 19 + Vite + TypeScript, TanStack Router
(file-based routes) + React Query, Tailwind + shadcn/ui. Backend: PocketBase
(SQLite + file uploads) behind an Elysia API on Bun. UI copy is Chinese; keep
that style.

## Layout

- `app/main.tsx` — entry: QueryClient, auth store, router, prod-only SW
  registration.
- `app/routes/` — file routes. `app/routeTree.gen.ts` is generated by the Vite
  plugin; never hand-edit it.
    - `__root.tsx` root layout; `_protected.tsx` auth gate; `_protected/_main.tsx`
      app shell (scroll area + bottom `NavButtons`).
    - `_protected/_main/{home,chat,jizhang,study,profile,report,dinner}/` feature
      pages; `/posts` and `/photos` only redirect to `/home`, which hosts the
      动态 feed under its greeting card. `chat/` has an index (conversation list)
      and `$conversationId.tsx` (thread), but its data/session/components live in
      `app/chat/`; `/dinner` is reached from the home bowl and has no bottom-nav
      tab.
    - Files starting with `-` (`-components/`, `-home/`) are route-private UI
      helpers, not routes. Query/mutation modules belong to the owning domain.
- `components/ui/` — forked shadcn primitives (see below). Biome lints it;
  `bun fmt` skips it. `components/` holds app components (`NavButtons`,
  `TouXiang`, `LoadingPage`, `EmptyState`, `MediaGrid`).
- Domains under `app/`: `chat/` (data/mutations, session run/resume, components,
  tools, streaming/SSE, prompts, personas, titles, records, gen-UI validation),
  `ledger/` (jizhang data, categories, summary, AI prompt), `home/` + `report/` +
  `profile/` (their queries and AI prompts), `feed/` (query/mutations, mixed
  media, comments, composer/viewer, AI captions), `dinner/` (wheel reducer,
  options), `notifications/`, `feedback/` (report data, realtime, attachments,
  issue state, filters, prompt, error buffer, shared draft hook), `ai/`
  (transport, cache, task store, generic sheets, `use-ai-feature.ts`), `study/` +
  `study/ai/` (study-only prompts and AI sheets), `about/`.
- `lib/` — `pb.ts` singleton + URL/date helpers, `auth-store.ts`,
  `auth.tsx`, `redirect.ts`, `env.ts`, `realtime.ts`, `postMedia.ts`,
  `query-keys.ts`, `toast.ts`, `toast-promise.ts`, image picker/compressor.
  `lib/contracts/` holds runtime-neutral types shared with `server/` (API error
  envelope, feedback rows, chat model metadata); it must not import React/DOM.
- `hooks/` — shared hooks (`use-infinite-list.ts`, back-dismiss, viewport).
- `server/` — the Bun API on Elysia:
    - `main.ts` only composes deps and calls `Bun.serve`; `app.ts` is the Elysia
      factory with the root lifecycle hooks and route plugins.
    - `http/` — auth, auth-gate, body caps, CORS, errors, request id, rate
      limiters, PocketBase REST client/admin token, logger.
    - `routes/` — health, ai, feedback, video, static.
    - `ai/` — relay, models, tools/_, sandbox/_; `feedback/` — service, github,
      admin, reports, markdown, types, limits.
    - `static.ts` serves the SPA; `geo-ip.ts`, `safe-fetch.ts`, `video.ts`,
      `request-body.ts` and the sandbox modules keep their contracts.
      `server/package.json` holds the server-only deps (elysia, ip2region,
      quickjs-emscripten). Read `docker/README.md` before touching deploys.
- `pocketbase/` — migrations, JSVM hooks (`ownership`, `post_counters`,
  `notifications`, `dev_seed`); `pb_data/` and the binary are gitignored.
- `docker/` + `compose.yaml` — app/PocketBase images, Caddy example, `.env.app`.
- `scripts/` — `pb-binary.ts`, `backends.ts`, `dev.ts`, `lan-proxy.mjs`,
  `preview.mjs`, `perf.mjs`, `check-bundle.ts`, `check-coverage.ts`,
  `pb-hooks-test.ts`. `tmp/` is gitignored scratch; never commit it.

## Commands

```bash
bun install
bun run install:server   # server/ deps (elysia, ip2region, QuickJS)
cp .env.example .env      # VITE_POCKETBASE_URL=same-origin
bun run dev:backend       # PocketBase :8090 + API :9001 (admin at /_/)
bun run dev:frontend      # Vite on :3000 (VITE_PORT=3001 to change)
bun run dev:all           # both, LAN-exposed (prints the phone URL)
bun run build             # vite build + shell budget + bun check
bun run preview           # build + serve build/ with /db and /api proxies
bun run test              # bun test (pure logic, no server or browser needed)
bun run test:coverage     # bun test + the aggregate line-coverage floor
bun run test:pb           # real-PocketBase hook tests (pinned binary)
bun run typecheck         # bun check for the app + server/
bun run lint              # biome lint
bun run format            # bun fmt
bun run format:check      # bun fmt --check
bun run setup:hooks       # enable .githooks/pre-commit once per clone
```

Formatting is Bun's native formatter (`bunfig.toml`), linting is Biome
(`biome.json`, lint only), typechecking is `bun check`. There is no `bun lint`;
don't reintroduce Prettier, an ESLint config or a second linter. Unit tests use
Bun's runner and cover pure logic only. Verify UI changes with `bun run build`
and the dev server, or `bun run preview` when no dev server fits.

`test:coverage` writes lcov to `tmp/coverage/` and `scripts/check-coverage.ts`
enforces the 78% aggregate line floor (ratchet it up, never down). `build` runs
`scripts/check-bundle.ts` against `scripts/bundle-budget.json`; the shell is
about 135KB gzip JS + 19KB CSS and must stay under 160KB/26KB. Raise a budget
only for a deliberate, reviewed increase. `test:pb` is not part of `bun test`:
it boots the pinned PocketBase binary with this checkout's migrations/hooks and
asserts ownership, counter and notification behavior.

Silence a rule with `// biome-ignore lint/<group>/<rule>: <reason>` on the line
Biome reports — for hooks, directly above the `useEffect`/`useMemo` call. Biome
ignores `eslint-disable`, and an ignore matching no finding is a hard error
(`suppressions/unused`), so move it with the code.

The production stack is `compose.yaml` + `docker/` (see `docker/README.md`):
`mimi-app` (Bun API + SPA) and `mimi-pb` (PocketBase + schema) on the host's
`caddy-net`, updated by Watchtower. Compose restarts the two containers; there
is no process manager of its own.

## Previewing the production build

`bun run preview` (`scripts/preview.mjs`) builds with
`VITE_POCKETBASE_URL=same-origin`, starts PocketBase + the Bun API, and serves
`build/` exactly like the self-hosted deployment: static files, SPA fallback,
`/db` proxied to PocketBase with the prefix stripped, `/api` proxied to the API.
It exists for memory-constrained machines: a Vite dev server holds ~430MB, the
preview plus backends ~120MB; the cost is one build per change (no hot reload).

- `PREVIEW_PORT` (4500), `PB_PORT` (8110), `API_PORT` (9110) are starting
  ports; busy ones are skipped, so several worktrees can share the defaults.
  The printed `preview ready: <url>` is authoritative. `PREVIEW_BUILD=0` reuses
  `build/`. One preview per worktree: starting it stops the previous preview or
  `dev:backend` stack recorded in this worktree's locks (even after SIGKILL).
  It waits only on ports it just freed, never kills another checkout's stack,
  and refuses to kill a recycled PID. Ctrl-C stops what it started.
- The build must be `same-origin`; a bundle for another origin bypasses `/db`.
- `DEV_BUILD=1` is baked in, so the login page keeps the 「开发账号」 card and
  `?dev=` URLs against the seeded database. `DEV_BUILD=0 bun run preview`
  builds without them to check the deploy's login page.
- Log in with `test@mimi.local` / `mimi123456`.
- `scripts/perf.mjs` is the same serving layout plus Playwright measurement.

### Driving the browser

Sign in through the URL, not the form: open the first protected route with
`?dev=test` (or `?dev=test2`) and let the auth gate log in, then wait for the
param to be stripped. Any protected route works; this saves scripting the
login form or clicking the 「开发账号」 card.

```js
await page.goto(`${base}/home?dev=test`, { waitUntil: "networkidle" });
if (page.url().includes("/login")) throw new Error("dev sign-in failed");
```

It works on the dev server and on `preview`; `DEV_BUILD=0` and production
builds fold it out, hence the explicit assert instead of assuming success.

Drive `playwright-core` directly; there is no screenshot script. It ships no
browsers, so pass `executablePath` for a system Chromium plus `--no-sandbox`
and `--disable-dev-shm-usage`. Never `bun add -d playwright`: its bundled
browsers are glibc builds that print a version and then segfault on
Alpine/musl.

## Performance

`bun run perf` measures the routes in Chromium at 390x844@2x with Fast 3G and a
4x CPU slowdown. The shell is ~135KB gzipped JS + 19KB CSS on every route; keep
heavy features lazy (the study bank is its own chunk) and re-run `perf` before
and after adding a heavy route. `bun run build` fails if the gzipped shell
crosses `scripts/bundle-budget.json`, so an accidental eager import is caught
before CI or the image build. A repeat visit is much faster because the service
worker serves the shell.

## Worktrees

Do feature work in its own worktree so `master` stays deployable.

```bash
cd <repo>
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install
bun run install:server
cp .env.example .env
bun run dev:all
```

- Convention: directory `../mimi-base-<topic>`, branch `feat/<topic>`. Run git
  from the environment that owns the checkout.
- Each worktree has its own `pocketbase/pb_data/` and `dev:all` stack; they can
  run side by side. One PocketBase per checkout: a second `dev:all` reuses it
  and only picks another Vite port.
- The PocketBase binary is copied from a registered worktree, a sibling
  checkout or `~/.cache/mimi-base/` (version checked); GitHub is contacted only
  when none has the pinned release. Never commit it.
- Ports auto-skip when busy (also on the Windows side under WSL). Pin them in
  `.env` (`VITE_PORT`, `PB_PORT`) for stable URLs; shell env wins.
- `MIMI_DEV_LOWMEM=1` starts Vite with `RAYON_NUM_THREADS=1` (peak ~1.96GB →
  ~1.55GB, ~10% slower first load). Opt in when RAM is short.
- `dev:all` prints the LAN URL. PocketBase and the API stay on loopback; Vite
  proxies `/db` and `/api`; dev uses `VITE_POCKETBASE_URL=same-origin`.
- Stop the servers before `git worktree remove <path>`. `.env` and `pb_data/`
  are gitignored, so removing the directory is enough.
- **Remove a worktree as soon as its branch is merged into `master` and
  pushed** — do not wait for the user to ask. Confirm the tree is clean and the
  branch is merged, then remove the worktree and delete the branch. Leave
  unmerged or dirty trees alone, and mention the cleanup in one line.

## Landing a worktree

`master` stays linear: rebase the branch onto `master`, then fast-forward.
Never merge `master` into a feature branch and never create a merge commit.

```bash
# in the worktree
git fetch origin
git rebase origin/master

# in the primary checkout
git switch master
git merge --ff-only feat/<topic>
git push
```

- If `--ff-only` refuses, the branch is not on top of `master`; rebase again.
- Re-run `bun run typecheck` and `bun run test` after the rebase; it replays
  each commit, so verify the final tree before it lands.
- Generated conflicts (`app/routeTree.gen.ts`, `bun.lock`): take `master`'s
  side and regenerate (`bun install`, then let the dev server rewrite the route
  tree); never hand-merge.
- Never rebase `master` or a branch that is pushed or checked out elsewhere
  (that needs `--force-with-lease` and breaks anyone based on it). Squash
  fixups with `git rebase -i origin/master` first.
- Back a topic out by reverting its range (`git revert <first>^..<last>`), not
  by hunting a merge SHA.
- Recommended once per clone: set `merge.ff=only` and `pull.rebase=true`.
- Push `master` only when the user asks; the worktree-removal rule applies once
  it is fast-forwarded and pushed.

## Commit messages

Keep messages short: a conventional, imperative subject, then at most one or
two short body lines saying what changed and why.

```text
fix(feed): insert a newline in the comment box

Enter now inserts a newline; only the send button posts.

Closes #99
```

Leave reproduction steps, screenshots and verification detail to the PR
description or issue thread; they do not belong in the commit body. When the
commit closes an issue, `Closes #N` stays on its own line after a blank line.
Do not rewrite a commit already on `master` just to shorten it.

## Update log

Record user-facing changes in both places **in the same commit**:

- `app/about/updates.ts` — the in-app 关于 log. Only what a user can notice;
  skip refactors, tooling and docs. Newest first, one entry per day (extend
  today's entry). Chinese copy with no file paths or internals. Bullets go under
  `added` / `fixed` / `changed`.
    - Fill `summary` for every entry: one sentence (≤ 45 chars) shown under the
      title. Write it as a benefit, not a list of internals.
    - Optional `highlight`: copy **one bullet verbatim** from the groups; it
      renders above them as 这次的重点 and is removed from its group.
    - Optional `links` (`{ label, to }`) to jump into the shipped feature; `to`
      is typed to the main app routes and must stay in-app.
    - The page is a timeline grouped by month; the newest entry opens by
      default. Media is deliberately unsupported; keep it text-first.
- `CHANGELOG.md` — the developer-facing record. Add a bullet under the matching
  `###` heading in today's `## YYYY-MM-DD` section, creating it above older
  sections. Include internal work users won't notice; both files describe the
  same batch, so keep them consistent. **Keep each bullet to one or two short
  lines**: the outcome plus the issue number. Implementation notes,
  reproduction steps and verification detail go in the PR or commit, not here.

`app/about/updates.test.ts` checks the in-app log's shape (real dates,
newest-first, at least one bullet, summary length, `highlight` matches a real
bullet, links are labelled in-app paths) and that every in-app date has a
matching `## YYYY-MM-DD` section in `CHANGELOG.md`. It cannot tell whether you
logged a change at all — that is on you. Never claim a feature the diff does
not contain.

## Parallel sessions

Several agents may run at once. The **primary checkout** (the first entry of
`git worktree list`) must stay clean: treat it as read-only. Every writing
session works in its own worktree.

If a task needs writes and `git rev-parse --show-toplevel` is the primary
checkout, create and move into a worktree yourself — do not ask the user to
start a new chat:

```bash
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install --frozen-lockfile
bun run install:server
cp .env.example .env
```

`--frozen-lockfile` keeps `bun.lock` untouched; contents come from the shared
Bun cache. `install:server` does the same for `server/package.json`. Re-check
`git rev-parse --show-toplevel` before your first commit.

- Stop any dev server in the primary checkout before switching, or it keeps
  regenerating `app/routeTree.gen.ts` in the old tree.
- If a tree you did not create has uncommitted work, ask before touching it.
  Never `git reset --hard`, `git checkout .`, `git stash` or `git clean` there.
- One topic, one worktree, one branch. If the directory or branch exists, pick
  a variant; never reuse it.
- Land one session at a time (see Landing a worktree), then remove the merged
  worktree.

## Backend / data rules

- Use the singleton `pb` from `lib/pb.ts`; don't create another client.
- PocketBase is mounted at `/db` (SDK base `<origin>/db`, admin at `/db/_/`);
  hand-written Bun endpoints live under `/api/*`. Vite proxies both. Production
  routes `/db/*` to `mimi-pb:8090` after stripping the prefix and `/api/*` to
  `mimi-app:9001`; `/feedback` stays the SPA route. `VITE_POCKETBASE_URL` may
  be a bare origin or end in `/db`; `lib/env.ts` normalizes it.
- The API is an Elysia app (`server/app.ts`). Its root lifecycle is the security
  contract: `onRequest` answers CORS preflight and authenticates
  `/api/ai|feedback|video` (except `/api/ai/health`) before any body is read;
  `onParse` enforces the per-route byte caps through `server/request-body.ts`;
  `onError` emits the single envelope `{ error: { message, code?, requestId? } }`
  (tool-level `{ ok: false }` at HTTP 200 is a payload, not an error). SSE,
  video and static handlers return raw `Response` objects. A new authenticated
  route belongs under one of those prefixes or the guard must be extended — do
  not read a large body in a handler that skipped `onRequest`. Auth is
  implemented once in `server/http/auth.ts` (hashed-token cache, 60s, shared
  6-slot gate); rate limits live in `server/http/rate-limit.ts` behind an
  injectable `CounterStore`; PocketBase access goes through `server/http/pb.ts`
  (one client, cached single-flight superuser token). Both the cache and the
  limiters are per-process by design (one `mimi-app` container); a second
  replica needs a shared store, not multiplied limits.
- Collections: `users`, `tou_xiang_circle`, `posts`, `comments`, `post_likes`,
  `comment_likes` (schema only, unused by the UI), `notifications`,
  `ji_zhang_biao`, `ji_zhang_category`, `study_progress`, `chat_conversations`,
  `chat_messages`, `chat_personas`, `chat_memories`, `chat_artifacts`,
  `dinner_options`, `feedback_reports`; `tu_pian_xin_xi` is legacy (migrated
  into `posts`).
- Every data collection is auth-only (`@request.auth.id != ""`); keep `posts`
  that way. **This is deliberate, not a leak.** The product has exactly two
  accounts for one couple, sign-up is locked, and the shared feed/ledger _is_
  the feature. Don't owner-scope posts/comments or add a friends system. Scope
  today: `study_progress` and all `chat_*` are owner-scoped;
  `ji_zhang_category` / `tou_xiang_circle` are owner-scoped for writes while
  reads stay auth-only (categories are filtered by `user_id` in the app, rings
  are shared); `feedback_reports` is owner-only for bug rows plus
  update/delete, while its read rule shares `kind = "feature"` rows with both
  accounts; `ji_zhang_biao` is shared for reads but owner-scoped for
  update/delete. If a third account is ever added, migrate the per-collection
  scope _before_ it exists. `notifications` is recipient-scoped: the recipient
  can only flip `read`; create/delete are server-only. Update rules see the
  **pre-update** row, so `pocketbase/pb_hooks/ownership.pb.js` restores
  `owner` / `author_id` / `user_id` and chat relations before saving; keep new
  ownership fields out of client updates. `feedback_reports.status` and
  `issue_*` are server-only (the hook skips superuser writes). `chat_messages`
  creates are rejected unless the conversation belongs to the caller; the same
  check covers `chat_attachments` / `chat_artifacts`. Feature suggestions drop
  `route` / `user_agent` / `console` / `conversation` because both accounts can
  read them. File fields are `protected`, so unauthenticated `/api/files/...`
  requests 404.
- Filters are parameterized (`pb.filter("post_id = {:postId}", {...})`); date
  literals use `pbDate(date)` (`YYYY-MM-DD HH:mm:ss.SSSZ`).
- File fields (`users.tou_xiang`, `tou_xiang_circle.image`, `posts.images`,
  `posts.videos`) store filenames, not URLs. Build URLs with `getFileUrl` /
  `getUserAvatarUrl` / `getUserCircleUrl`, which append the short-lived token;
  never call `pb.files.getURL` for them (an `<img>` cannot send the auth header,
  so a tokenless URL 404s). URL tokens expire after ~3 minutes; a rendered
  `<img>` keeps its original src, so `lib/protected-image.ts` retries once with
  a fresh token on error. Feedback attachments are **not** PB files: the row
  stores `{ name, url, size, type }` metadata pointing at GitHub release assets.
- Feedback flow for both kinds: upload attachments
  (`POST /api/feedback/upload`, max 3 × 10MB) to the `feedback-assets` GitHub
  prerelease, create `feedback_reports` (bug/feature, attachments JSON, optional
  `chat_conversations` for bugs), then `POST /api/feedback/report`. Attaching a
  conversation starts in the chat thread's 反馈问题 menu (`/feedback?conversation=`);
  the page has no conversation picker. The API authenticates with the caller's
  PB token, re-reads the row, and still requires `report.owner === caller` — the
  shared feature read rule never authorizes a sync. There is no per-user
  submission cap. `GITHUB_TOKEN` / `GITHUB_REPO` / `GITHUB_API_URL` /
  `GITHUB_UPLOADS_URL` are server-only; **never** send them or the PB token to
  the browser. Missing token/repo keeps a text report `stored` (UI: 待同步) and
  the card can retry; attachment uploads return 503 and create no row. GitHub
  failures set `status=failed` without losing the report; retrying a synced
  report reuses its issue. Bug issues are `[Bug]` + `bug`/`from-app` and may
  include the last 20 console errors and a server-fetched transcript of the last
  20 chat messages / 10k chars. Feature issues are `[Feature]` +
  `enhancement`/`from-app`, never fetch a transcript, and include inline
  attachment links. 大家的建议 is shared; 我的反馈 is owner-only. Both lists page
  20 rows (`useInfiniteQuery` + `getList`, `FEEDBACK_PAGE_SIZE`, `fields` keeps
  `console`/`user_agent` off the wire) and count `totalItems` from page 1.
  `useFeedbackRealtime` registers reducers for both list keys: create prepends
  (then fetches that row to expand the author), update merges while keeping
  `expand`, delete removes. Unclaimed events still fall back to prefix
  invalidation; this is what stops the issue-state write-back from retriggering
  itself. `POST /api/feedback/issue-state` (auth-only, max 50 ids) re-reads rows
  with the caller's token, refreshes only `issue_created` rows not already
  `closed` (60s cache), and treats a stored `closed` as terminal; a GitHub read
  failure leaves the stored label. Writes use `SUPERUSER_EMAIL` /
  `SUPERUSER_PASSWORD` from `.env.app` (dev: `dev@mimi.local`) so shared
  suggestions persist for the non-owner. `issue-state` is rate-limited per user
  (6/min, 50/day); request bodies go through `server/request-body.ts` so a
  chunked upload still respects the route's byte cap. Video compression runs at
  most 2 at a time, and only a spawn failure disables ffmpeg (a malformed MP4
  must not poison the service).
- Avatar rings: `users.circle_preset` stores a built-in key
  (`components/TouXiang/presets.tsx`; `""` = default, `"none"` hides it);
  `users.circle` points at an uploaded `tou_xiang_circle` row scoped by
  `owner`. Render with `getUserRing(user)` so the upload wins.
- `author_id` / `user_id` relations have no DB default — always send them.
- `posts.like_count` / `comment_count` are denormalized and maintained by
  `pocketbase/pb_hooks/post_counters.pb.js`; never bump them on the client. The
  delete hook also runs for cascaded replies. Feed reads are patched in place
  by `app/feed/realtime.ts` (one debounced counter `getOne` per touched post);
  never invalidate `qk.posts.all` from a like/comment mutation or reducer — an
  infinite-query invalidation refetches every loaded page.
- Interaction notifications are created only by `notifications.pb.js`: likes
  notify the content author, comments notify the post author, replies notify
  the parent author (and the post author when different); self-actions are
  skipped. Unlike/comment deletes remove rows; post/comment/account deletion
  cascades. The inbox expands `actor`, `post` and `comment`;
  `/home?post=<id>&comments=1` filters to that post and opens its comments.
- Every `onRecord*` hook runs in one chain and its handler must call `e.next()`.
  For `onRecord*Request` it is **middleware**: skipping it ends the request with
  `200` + an empty body and saves nothing, while the client SDK resolves it as
  success. After-create/after-delete hooks are chained the same way: both
  `notifications.pb.js` and `post_counters.pb.js` listen on `post_likes` /
  `comments` (files load in random map order), so a handler that returns without
  `e.next()` stops the other counter or notification. Call it on every branch,
  including early returns. `post_counters.test.js` scans every handler for a
  missing `e.next()` and for a bare `return;`; the create/update mutations also
  refuse a response without a record id.
- `comments.parent_id` supports unlimited depth; `buildCommentThreads` groups
  descendants under the top-level comment and the UI shows `回复 @name`. Send
  `""` for a top-level comment.
- A post carries ONE ordered media set (#80). `posts.images` holds up to 9
  photos and `posts.videos` up to 9 MP4/WebM/MOV clips (50MB, protected); the
  composer enforces a combined cap of 9 (`MAX_POST_MEDIA`) with one picker
  (`MEDIA_ACCEPT`) and one sortable grid. Upload both fields in the same
  `FormData`; `images: ""` / `videos: ""` clears a field. `posts.media_order`
  stores `[{type,index}]` into the final arrays (kept files first, then new
  uploads); malformed/old values fall back to video-first + image order and are
  completed defensively (`resolveMediaOrder`). `posts.media_meta` stores
  positional `{width,height}` so the feed reserves the real box before the
  protected files load; old rows measure on load. `posts.layout` is `instagram`
  (full-bleed carousel) or `twitter` (timeline, action row under the media);
  the retired `moments` value is folded into `twitter` by `toPostData`, as is
  any row with no photos/video. Tweet-layout clips autoplay muted at 60%
  visibility (paused off-screen, honouring `prefers-reduced-motion`); the 大图
  layout never autoplays and uses square slides, with a lone clip keeping the
  full-size player. First frames come from `#t=0.1` on the protected URL
  (`lib/postMedia.ts`). AI captions use photos only; a clip-only post uses the
  text hint.
- `ji_zhang_biao.category` is free text: a built-in key (`food`, `takeout`,
  `transport`, `shopping`, `home`, `fun`, `health`, `other` from
  `app/ledger/categories.ts`) or a `ji_zhang_category` row id. Resolve with
  `useExpenseCategories().getCategory` / `getExpenseCategory`; unknown or
  deleted values render 其他, old empty rows stay empty. Renaming a custom
  category is safe (rows point at the id); deleting first clears those rows to
  `""` so 补全分类 can pick them up. Never hardcode a new category in a
  migration's `values`; the field is no longer a select.
- `pb.authStore.record` has no `expand`; fetch the profile with
  `expand: "circle"` (see `lib/auth.tsx`).
- Schema changes go in a new committed migration under
  `pocketbase/pb_migrations/`. Never edit an applied migration. Runtime data
  (`pb_data/`) is gitignored.
- Dev seeding: `scripts/backends.ts` starts PocketBase with `MIMI_DEV=1`, which
  makes `dev_seed.pb.js` create `test@mimi.local` / `test2@mimi.local` (both
  `mimi123456`) and the dashboard superuser `dev@mimi.local` / `mimi123456`
  when missing (never overwritten). Reset one from `pocketbase/` with
  `./pocketbase superuser upsert <email> <password>`. Production never sets the
  var, so none of these exist there. Dev builds list both accounts on the login
  page, accept `?dev=test` / `?dev=test2` on any protected URL, and the profile
  page switches between them in place (`lib/dev-accounts.ts`,
  `ensureDevSession`). `DEV_ACCOUNTS` is empty unless `import.meta.env.DEV` or
  the `DEV_BUILD` define is set, so deploy bundles drop it.

## Frontend conventions

- `@/*` maps to the repo root; use it instead of deep relative imports.
- `bun fmt` uses `bunfig.toml` (4 spaces, double quotes, 80 cols, trailing
  commas, Tailwind class and import sorting). `biome.json` mirrors the old
  ESLint bar: a11y and React-Compiler-era rules are off,
  `useExhaustiveDependencies` is `warn` with unnecessary deps ignored. Don't
  add a second linter or formatter.
- Data fetching lives in the owning domain (`app/<domain>/data.ts(x)` for feed,
  chat, ledger, home, report, profile, notifications, feedback, dinner and
  study). Route-private `-data` modules are only for truly page-local state, not
  for another route to import. Define every key in `lib/query-keys.ts`
  (`qk.*`); per-user keys include the user id, and mutations invalidate the
  `qk.*.all` prefix. Use `useQueryClient()`, never import `queryClient` from
  `app/main`.
- Auth: `lib/auth-store.ts` owns the snapshot (`status` + `user`);
  PocketBase holds only the credential. `lib/auth.tsx` creates the single
  instance and exposes it via `useAuth()` (`useSyncExternalStore`). The router
  context is built once in `app/main.tsx` and must never change identity.
  `useAuth().user` is nullable; protected screens use `useCurrentUser()`. Guards
  await `auth.waitForAuth()` and branch on `status`; `login()` resolves only
  after the profile is stored. Login/sign-out bump a generation so an older
  profile read cannot overwrite the newer account. Don't paper over auth
  loading with `router.invalidate()`.
- Post-login targets go through `lib/redirect.ts` (`toLoginTarget`,
  `hrefWithoutDev`). Never build a login URL by hand; it nests on every render.
- Account switching is logout-based: 个人资料 → 账号 → 退出登录 clears the query
  cache and returns to `/login`. Dev builds switch seeded accounts in place.
- `vite.config.ts` enables `autoCodeSplitting`. Keep heavy feature data behind
  route imports; don't import the study bank from the shell.
- AI infrastructure lives in `app/ai/`, mounted in `_main.tsx` via
  `AiProvider`. `client.ts` supports text, streaming, JSON and vision
  (`visionMessage` + `imageToDataUrl`, downsized to 1024px JPEG). Feature
  prompts live with their owner (`app/ledger/ai.ts`, `app/feed/ai.ts`,
  `app/home/ai.ts`, `app/report/ai.ts`, `app/study/ai/`); `app/ai` must not
  import a feature domain. Only what a feature builds locally is sent to the
  provider; nothing
  AI-related is written back except user-confirmed expense rows/categories. A
  503 keeps the original text and the 反馈 form still submits.
  **The site owns the only key; there is no BYOK path.** The Bun API mounts
  `server/ai/relay.ts` at `/api/ai/opencode/v1/chat/completions` (legacy path, forces
  the configured model) and `POST /api/ai/chat/completions` + `GET /api/ai/models`
  for chat: the model must be in the server allowlist
  (`server/ai/models.ts`, narrowed by `AI_CHAT_MODELS`), unknown ids get 400,
  text-only models lose `tools`, non-vision models reject images, and
  `reasoning_effort` is checked against `thinkingLevels`. Keys and quotas
  (`AI_API_KEY`, `AI_API_URL`, `AI_MODEL`, `AI_CHAT_MODELS`,
  `AI_CHAT_MODEL_DEFAULT`, `AI_DAILY_REQUESTS_PER_USER`) come from `.env.app`
  (dev: `.env`) and never reach the browser, PocketBase or logs.
  `AI_API_URL` is an optional OpenAI-compatible base (the relay appends
  `/chat/completions`); for local no-cost tests run
  `bunx emulate --service ai`, set it to `http://127.0.0.1:4000/v1`, and use
  any `AI_API_KEY`. Only notification/budget prefs live in
  `localStorage` (`mimi:ai:v1`);
  old saved API keys are scrubbed on load. Generated content is cached under
  `mimi:ai-cache:v1:*`; keys derived from progress include the user id, and
  `app/ai/reset.ts` clears the cache + interrupted ledger on logout/account
  switch (`noteCurrentUser` also catches a direct A→B switch).
  Production Caddy routes `/api/*` to `mimi-app:9001` with
  `flush_interval -1`; Vercel derives the API origin from
  `VITE_POCKETBASE_URL`. Video posts use `POST /api/video/compress`
  (auth-only, max 50MB, optional `ffmpeg`/`FFMPEG_PATH`, ≤1280px H.264/AAC);
  clips compress one at a time, files under 8MB skip it, failure or a
  non-smaller result publishes the original, and the endpoint never stores it.
- Long AI requests go through `AiTasksProvider` (`app/ai/tasks.tsx`): use
  `runTask({ key, group, cacheKey, title, run })` and let the store own the
  `AbortController`; never abort on unmount/close. Results land in `cacheKey`
  and the task center; `attend(group)` suppresses duplicate notifications while
  a panel is open. Closed panels restore with `decideAiRestore`
  (`app/ai/restore.ts`). Standard panel features should use
  `app/ai/use-ai-feature.ts` (cache read, restore decision, task, cache write);
  streaming editors and multi-key flows may keep their own state. System
  notifications are opt-in (`AiSettings.notify`) and fire only while the page is
  hidden. Reloading or closing the app still stops in-flight work; the store is
  memory-only.
- General chat (`app/chat/`, `/chat`): assistant-ui primitives +
  `useExternalStoreRuntime`; messages persist in `chat_messages` as content
  parts. A run loops up to 6 model rounds while calling `sandbox_*` tools. Run
  state (live draft, optimistic rows, abort, sandbox files/watchers) lives in
  `app/chat/run-store.ts` keyed by conversation id — **not** in
  `useChatSession` state. Leaving the thread keeps the run going; re-entering
  re-attaches and refuses a second send until it ends. A pending `ask_user`
  carries its conversation id and survives navigation; only stop/logout cancels
  it. The sandbox is **JavaScript in QuickJS** on the server: one fresh runtime
  per run in a Worker, 64MB heap, 60s hard limit via `worker.terminate()`, fresh
  in-memory text snapshot. No filesystem, `fetch`/`process`/`require` or
  network; the only bridge is `console.*` and
  `sandbox.read/write/list/remove/fetch/download`. `fetch`/`download` go through
  `server/safe-fetch.ts` (same DNS/private-range/redirect guard as `read_url`)
  and return a QuickJS Promise bridged from native fetch
  (`server/ai/sandbox/sandbox-promise.ts`) — not an asyncified host function,
  which traps on a second success in one run. Each run shares a host-fetch
  budget (`server/ai/sandbox/sandbox-budget.ts`: 4 concurrent, 30 total) because
  native fetch
  buffers are not bounded by the QuickJS heap. `sandbox.fetch` resolves to the
  body text, so `JSON.parse(await sandbox.fetch(url))` is the pattern. Python is not
  supported. Don't expose new host globals without re-evaluating prompt
  injection against the AI key and `pb_data`. `ask_user` is client-side and
  pauses the loop (text/choice/confirm/location). Location is a
  **city-only IP estimate**: `GET /api/ai/geo/ip` is called only after the user
  taps 自动识别城市, the estimate is confirmed before reaching the model, and
  coordinates are never resolved or injected silently. `log_expense` also
  pauses; the row is written only after 「记下」 and still goes through the
  owner-bound rule.
- Gen UI (`show_chart` + `render_ui`) is client-side and data-only.
  `show_chart` draws one bar/line/pie with a validated style using
  `--chart-1..6`. `render_ui` accepts a whitelist of blocks from
  `app/chat/ui-spec.ts` (text/metrics/list/table/progress/badges/chart/divider;
  max 12 blocks and a 12k serialized spec). No HTML/CSS/JS, remote URLs,
  buttons, forms or links. Map enum values to fixed literal theme-token classes
  so Tailwind emits them and dark mode works.
- Chat data tools (`/api/ai/tools/{expenses,posts,comments,memory,url}` in
  `server/ai/tools/*`) are the only way the model reads site data; the server,
  not the persona prompt, is the security boundary. It authenticates,
  rate-limits (30/min) and quotas (200/day), scopes rows with explicit PB
  filters (ledger/posts/comments shared on purpose; `chat_memories` owner-only
  with PB rules as backstop), and `read_url` resolves DNS once, pins the
  validated address for the connection (no rebinding), and refuses
  private/reserved hosts. Redirects are followed at most 3 times, re-validating
  each hop. The system prompt says tool output is
  data, not instructions — keep that line in `app/chat/prompt.ts`. Memories
  (top 30) are injected into every run and managed in 「AI 的记忆」.
- Built-in personas (`app/chat/personas.ts`, UI: 应用场景) are 日常对话 /
  写作润色 / 英语学习 / 基地管家 with starters. A conversation snapshots the
  persona name+prompt, so editing a built-in never rewrites old chats. Personas
  are prompts only — never gate capabilities on them.
- Chat affordances: search/filter/pin, edit-and-resend, fork, one-off retry
  with another model, Markdown export, document attachments, pick images from
  posts, PWA share target, read-aloud. The composer's send button is a custom
  handler: it sends queued images/docs even with empty text and disables while
  a document is still being read. Code blocks highlight with a lazy Shiki
  chunk (JS regex engine, no wasm). Attachments are stored in
  `chat_attachments` (owner-scoped, protected) and read on-device: text files
  are decoded in the browser, PDFs are rasterized by a lazy pdf.js chunk
  (`app/chat/pdf.ts` + `pdf-browser.ts`). `vite.config.ts` serves pdf.js
  CMaps/standard fonts from `node_modules` in dev and copies them to
  `build/pdfjs/` for Vercel/Docker/preview; without them some Chinese PDFs
  render blank. `read_attachment` serves persisted text or fetches the stored
  bytes and renders the requested pages locally. pdf.js is never loaded until
  a PDF is actually read, and `/api/ai/files` is gone. pdf.js's Node-only
  optional `@napi-rs/canvas` is overridden to `empty-npm-package` in the root
  `package.json`, so installs do not fetch the native binary; the browser
  draws into the DOM canvas. Caps: 30MB, 50k chars, 10 inline pages, 4 images
  (`lib/chat-files.ts`). Every API service authenticates through the shared
  `server/http/auth-gate.ts` slot (max 6 concurrent `auth-refresh` calls) to
  blunt random-token floods.
- Chat artifacts: text files stay in `chat_conversations.sandbox_files` and the
  part references the path; binary images come back once in `sandbox_run`
  (base64), upload to `chat_artifacts` (owner-scoped, protected, cascade), and
  the part stores id + filename. HTML/SVG must render in `<iframe sandbox="">`
  (no `allow-same-origin`, no scripts) with the injected `default-src 'none'`
  CSP — never inline or in a Shadow DOM, which is not a security boundary.
- Add a page: `app/routes/_protected/_main/<name>/index.tsx` with
  `createFileRoute("/_protected/_main/<name>/")`, let the dev server regenerate
  `routeTree.gen.ts`, then add a nav entry in `components/NavButtons/index.tsx`.
  Start with `components/PageHeader` (`backTo`, `description`, `actions`;
  `compact` only for an in-thread bar) so spacing stays consistent. `/home` is
  the exception: its greeting card owns the top of the feed.
- Shared interaction primitives: `components/EmptyState` for empty lists,
  `components/MediaGrid` + `MediaTile` for removable/selectable/sortable media,
  `components/ui/tabs` and `components/ui/select` for the accessible tablist and
  native select, and `hooks/use-infinite-list` for infinite-query flattening.
  Use `components/ConfirmDialog` instead of `window.confirm`; do not hand-roll a
  sixth media grid or a local empty state.
- Style with Tailwind + `components/ui` + `cn()`. No CSS modules; nav icons are
  lucide. Use semantic tokens (`bg-card`, `text-muted-foreground`,
  `border-border`, `shadow-soft`) so both schemes work; `ThemeProvider` is in
  `lib/theme.tsx` and persists under `mimi-theme`.
- v4 emits `hover:` behind `@media (hover: hover)`; a touch tap latches
  `:hover` until the next tap, so use `active:` or state classes for touch
  feedback.
- Use `toastPromise` for async user actions.
- Overlays must close on the mobile back gesture instead of navigating away.
  `lib/useBackDismiss.ts` handles `Dialog`, `Sheet`, `Drawer` and `AiSheet`;
  hand-rolled full-screen surfaces (e.g. `QuizRunner`) must call it themselves.
  It keeps one shared history entry and unwinds nested overlays one at a time.
  `AiSheet` is a Radix dialog on purpose: a plain `div` over a `Drawer`/`Dialog`
  is "outside" for them and would close the sheet underneath.
- The shell assumes `100dvh`; keep page scrolling inside the `_main` outlet.
- Accessibility: keep the global `:focus-visible` outline, don't add
  `outline-none` to interactive elements, label icon-only controls, and rely on
  the `prefers-reduced-motion` block in `globals.css`. `_main.tsx` ships a skip
  link to `#main-content`.

## Forked shadcn primitives

`components/ui/` is a **fork**, not pristine `shadcn add` output. Five files
carry customizations that must survive any refresh:

- `dialog.tsx` — `Dialog` calls `useBackDismiss`; `DialogContent` adds
  `overlayClassName`, `showCloseButton` and `mobileSheet` (bottom sheet below
  `sm`, centered above; used by `ConfirmDialog`).
- `sheet.tsx` — `Sheet` calls `useBackDismiss`.
- `drawer.tsx` — `Drawer` calls `useBackDismiss` and defaults
  `repositionInputs={false}` (our keyboard handling sizes the sheet).
- `sonner.tsx` — theme-aware `Toaster` driven by `useTheme()`.
- `form.tsx` — `FormItem` uses `[&>*+*]:mt-2` instead of `space-y-2`; v4 puts
  the gap on the preceding inline `<label>`, where vertical margins are ignored.

`components.json` records the fork (`x-mimi-fork`). **Do not regenerate these
files** without re-applying the customizations (or moving them into wrappers and
re-pointing every importer).

Tailwind is **v4 and CSS-first**: no `tailwind.config.js`. The theme is in
`globals.css` (`@theme inline`, `--radius` scale), dark mode is
`@custom-variant dark (&:is(.dark *))`, `tw-animate-css` replaces
`tailwindcss-animate`, and `@source` pins `index.html` + `app/` + `components/`.
Vite loads it through `@tailwindcss/vite`; there is no PostCSS config.
`* { @apply border-border }` keeps v3's border default, `rounded-*` maps to the
app's own scale, and v4 renames are migrated (`outline-hidden`, `shadow-xs`,
`bg-linear-to-*`, `!` as a suffix).

## Gotchas

- Router context (`auth`, `queryClient`) is injected in `app/main.tsx`; add new
  root keys in both the router and `__root.tsx`.
- Typechecking is `bun check` only. There is no separate `tsc` script and the
  `typescript` package is intentionally absent (Vite resolves tsconfig `paths`;
  the router plugin doesn't need it). Keep `"types": ["bun"]` and no `baseUrl`.
  The root `tsconfig.json` excludes `pocketbase/` and `server/`, so CI/Vercel
  builds don't need server deps.
- React 19 + `@react-three/fiber` 9 / `drei` 10: `useRef` needs an initial
  value, and the global `JSX` namespace is gone — use `React.JSX`. The study 3D
  scenes are the r3f compatibility surface; keep `three` at the version in
  `package.json`.
- `server/` is a separate manifest/lockfile. It depends on Elysia plus
  ip2region/QuickJS; Docker installs it with `bun install --production
--frozen-lockfile` from `server/`. The root `bun check` excludes `server/`, so
  `bun run typecheck` runs both.
- Run `bun run setup:hooks` once per clone; the pre-commit hook runs
  `bun fmt --staged`, typecheck, tests, lint and `format:check`.
- `APP_VERSION`, `APP_SHA` and `DEV_BUILD` are Vite `define` globals
  (`vite-env.d.ts`), not env vars. `DEV_BUILD` is true only for
  `bun run preview`; never set it for a deploy. The app shows the build sha;
  there is no release-bump step.
- `pb.autoCancellation(false)` in `lib/pb.ts` is intentional: the feed and like
  queries would otherwise abort each other.
- PocketBase records use `created`/`updated`; app types map them (`createdAt`).
- Build output is `build/` (not `dist`). `vercel.json` rewrites all paths to `/`
  for SPA routing. Vercel and the self-hosted stack serve **two separate
  builds**: Vercel builds from the repo; `docker/app.Dockerfile` builds with
  `VITE_POCKETBASE_URL=same-origin` and the Bun API serves `/app/build`.
- PWA: `public/sw.js` is hand-written with a build-injected `VERSION`; change
  it only when caching behavior changes. It registers only in production
  builds (`lib/service-worker.ts`). New workers wait for `SKIP_WAITING`; the
  app shows "有新版本可用" and reloads only after the user accepts. Navigation
  failures fall back to the cached shell, then an inline offline page. A
  chunk-load error never reloads while `navigator.onLine` is false, and the
  idle tab prefetch is skipped offline.
- PWA share target: `public/manifest.json` declares POST
  `multipart/form-data` with one `image/*` field (`media`). `sw.js` handles
  `POST /share` before its GET branch, stores the first image in the
  `mimi-share` cache (1h TTL) and 303s to `/jizhang?share=<id>`; image shares
  are image-only (the share sheet's title/text is ignored). Text shares go to
  `/share`. `-shared-receipt.ts` mirrors the cache name, `/jizhang` consumes
  the one-shot param and auto-parses it. A stray `POST /share` on the server
  303s to `/share?stale=1` so the page can ask for a reopen (iOS Safari has no
  `share_target`; use the gallery picker). Installed PWAs may need a relaunch
  (sometimes a reinstall) before the new share target appears.
- `lib/env.ts` validates `VITE_POCKETBASE_URL` at module load; missing crashes
  the app immediately.
- Pushing to `master` runs `.github/workflows/images.yml`: `ci` gates it, the
  `changes` job decides which image changed, both are pushed to Tencent Cloud
  Container Registry Hong Kong
  (`hkccr.ccs.tencentyun.com/<ns>/<name>:latest`, plus `:$sha`) using
  `DOCKER_REGISTRY` / `DOCKER_NAMESPACE` / `DOCKER_USERNAME` /
  `DOCKER_PASSWORD`, then `deploy` **POSTs** to Watchtower
  `/v1/update?image=...` (1.18 answers 405 to GET) and verifies `/version.json`.
  The TCR repos are **private**: the host has a one-time
  `docker login hkccr.ccs.tencentyun.com` in `/root/.docker/config.json`, which
  Watchtower also mounts (restart it after logging in). A registry or image-name
  change needs a one-time manual `docker compose pull && up -d` on the host.
  The old `/db/sync`, `/spa/publish`, `/repo/sync` and `/spa/rollback` endpoints
  are gone; `DEPLOY_TOKEN` is unused.
- Both containers auto-update through Watchtower, so **migrations must stay
  additive**: add fields/collections first, remove or rename in a later
  release, and keep the app tolerant of the previous schema. PocketBase
  scheduled backups are the rollback safety net.
- Never commit `.env`, `.env.app`, `pocketbase/pb_data/` or `tmp/`.
