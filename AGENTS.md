# AGENTS.md

## What this repo is

`mimi-base` ("秘密基地") is a personal, mobile-first PWA for sharing photos,
posts, and expense records. Frontend: React 18 + Vite + TypeScript, TanStack
Router (file-based routes) + React Query, Tailwind + shadcn/ui. Backend:
PocketBase (SQLite + file uploads) run by a Bun supervisor. UI copy is
Chinese; keep that style when adding user-facing text.

## Layout

- `app/main.tsx` — entry: QueryClient, auth store, router, prod-only SW
  registration.
- `app/routes/` — TanStack Router file routes. `app/routeTree.gen.ts` is
  generated by the Vite plugin; never hand-edit it.
    - `__root.tsx` root layout; `_protected.tsx` auth gate; `_protected/_main.tsx`
      app shell (scroll area + bottom `NavButtons`).
    - `_protected/_main/{home,posts,chat,jizhang,study,profile,report,photos}/`
      feature pages. `/posts` and `/photos` now redirect to `/home`, which
      hosts the 动态 feed under its greeting card. `chat/` has an index
      (conversation list) and `$conversationId.tsx` (thread).
    - Files starting with `-` (`-data.tsx`, `-comments.ts`, `-components/`) are
      colocated helpers, not routes.
- `components/ui/` — shadcn/ui primitives. These are a **fork** (see
  "Forked shadcn primitives" below): `dialog.tsx`, `sheet.tsx`, `drawer.tsx`,
  `sonner.tsx` carry hand-applied customizations and must not be regenerated.
  Biome lints this directory too (rules in `biome.json`); `bun fmt` still
  skips it.
- `components/` — app components (`NavButtons`, `TouXiang`, `LoadingPage`).
- `app/chat/` — general-chat domain logic: `api.ts` (relay URLs and allowlist
  fetch), `stream.ts` and `sse.ts` (streaming/tool-call parsing), `prompt.ts`,
  `personas.ts`, `title.ts`, `records.ts`, `chart.ts` / `ui-spec.ts` (gen-UI
  payload validation), and `tools.ts` (the server-side sandbox itself lives in
  `pocketbase/sandbox/`).
- `app/feed/` — 动态 domain: `data.ts` (infinite query and post mutations),
  `utils.ts`, `comments.ts`, and `components/` (post, composer, comment sheet,
  image viewer, video player/viewer, find sheet). Home renders the feed
  through the lazy chunk
  `_main/-home/feed.tsx`; `/posts` only redirects to `/home`.
- `app/feedback/` — feedback domain for both kinds: `data.ts` (attachment
  upload + bug/feature report create + supervisor sync + owner-only bug list +
  shared suggestion query + persisted/refreshed GitHub issue state),
  `attachments.ts` (metadata parse/display), `issue-state.ts` (issue state
  parsers for the row field and the supervisor response),
  `filters.ts` (visibility helpers mirroring the PB rules),
  `error-buffer.ts` (20-entry console/page-error ring buffer),
  `validation.ts`, `prompt.ts` (bug and feature AI tidy-up). The page lives at
  `_main/feedback/` with 问题反馈 / 功能建议 tabs (`?tab=feature` deep link);
  both entries sit in the profile page's 功能 section.
- `lib/` — `pb.ts` (PocketBase singleton + URL/date helpers), `auth-store.ts`
  (auth state, no React), `auth.tsx` (the app's auth binding), `redirect.ts`
  (in-app redirect targets), `env.ts`, `toast-promise.ts`, `date.ts`, image
  picker/compressor.
- `hooks/` — shared hooks.
- `pocketbase/` — server side: `server.ts` supervisor, `ai-files.ts`
  attachment reader, `feedback.ts` (report -> GitHub issue), `video.ts`
  (ffmpeg video compression), `package.json` / `bun.lock` (server-only pdf.js +
  canvas), `pb_migrations/` (schema), `pb_hooks/` (JSVM counters). Read
  `pocketbase/README.md` before touching deploys or the server.
- `public/` — PWA `sw.js`, `manifest.json`, images.
- `scripts/server-setup.sh` — fresh-server bootstrap. `scripts/dev.ts` backs
  `bun run dev:all` on Linux, WSL2 and plain Windows. Under WSL it also runs
  `scripts/lan-proxy.mjs` with the Windows node to forward the Vite port to the
  VM (no admin or portproxy required). PocketBase stays on loopback; Vite
  proxies `/api` and dev runs with `VITE_POCKETBASE_URL=same-origin`.
  `tmp/` is gitignored scratch (do not commit).

## Commands

```bash
bun install
bun run install:server   # pocketbase/ deps (pdf.js + canvas) for the supervisor
cp .env.example .env      # VITE_POCKETBASE_URL=http://127.0.0.1:8090
bun run db                # PocketBase on 127.0.0.1:8090 (admin at /_/)
bun run dev               # Vite on :3000 (VITE_PORT=3001 to change)
bun run dev:all           # both, always LAN-exposed (prints the phone URL)
                          # skips busy ports (WSL + Windows) and reads
                          # VITE_PORT/PB_PORT from .env; one instance per
                          # worktree is safe to run side by side
bun run build             # vite build + bun check (app; no server deps needed)
bun run test              # bun test (whole repo; pure logic, no server needed)
bun run typecheck         # bun check for the app + pocketbase/
bun run lint              # biome lint (biome.json)
bun run format            # bun fmt
bun run format:check      # bun fmt --check
bun run setup:hooks       # enable .githooks/pre-commit once per clone
```

Formatting is Bun's native formatter (`bunfig.toml`), linting is Biome
(`biome.json`, lint only), and typechecking is `bun check`
(`bun run typecheck`). There is no `bun lint`; don't reintroduce Prettier, an
ESLint config, or a second linter. Unit tests use Bun's built-in runner and
cover pure logic only; `bun test` scans the whole repo. Verify UI changes with
`bun run build` and the dev server.

Silence a rule with `// biome-ignore lint/<group>/<rule>: <reason>` on the line
Biome reports — for hooks that means directly above the `useEffect`/`useMemo`
call, not above the statement that looks wrong. Biome ignores
`eslint-disable` comments, and an ignore that matches no finding is a hard
error (`suppressions/unused`), so move the comment with the code.

## Performance

`bun run perf` builds the app, boots PocketBase, serves `build/` the way the
self-hosted deployment does (gzip, SPA fallback, `/db` and `/api` proxies) and
measures the routes in Chromium at 390x844@2x with Fast 3G (1.6Mbps, 150ms
RTT) and a 4x CPU slowdown. Playwright is deliberately not a repo dependency;
the script prints the two commands if it is missing.

Measured 2026-11-10, after the Tailwind v4 and date-fns work:

| route      | LCP  | FCP   | CLS | long tasks | requests | transfer |
| ---------- | ---- | ----- | --- | ---------- | -------- | -------- |
| `/home`    | 2.2s | 0.95s | 0   | 2 / 272ms  | 74       | 159KB    |
| `/jizhang` | 1.8s | 0.95s | 0   | 2 / 269ms  | 58       | 155KB    |
| `/chat`    | 1.7s | 0.95s | 0   | 2 / 184ms  | 51       | 152KB    |
| `/study`   | 1.5s | 0.84s | 0   | 1 / 133ms  | 34       | 150KB    |

- Every route pays for the same shell: ~131KB of gzipped JS plus 18KB of CSS.
  LCP on `/home` is a feed paragraph, i.e. it waits for the feed query; the
  greeting card paints at FCP.
- A repeat visit is much faster because the service worker serves the shell:
  `/home` LCP drops to ~0.9s once the worker controls the page.
- Chunk granularity is already one chunk per route (139 chunks, 53 under 3KB).
  Merging the router's component/pending/error split groups changed nothing
  measurable (139 → 138), so don't bother.
- If you add a heavy route, keep it lazy and re-run `bun run perf` before and
  after; the table above is the budget to beat.

## Worktrees

Do feature work in its own worktree so `master` stays deployable.

```bash
cd <repo>
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install
bun run install:server
cp .env.example .env
bun run dev:all
```

- Convention: directory `../mimi-base-<topic>`, branch `feat/<topic>`.
- Run git from the environment that owns the checkout (native shell for a
  native clone, inside WSL for a WSL checkout).
- Each worktree has its own `pocketbase/pb_data/` (own database) and its own
  `dev:all` stack; they can run side by side.
- The PocketBase binary is copied automatically from a registered worktree, a
  sibling checkout, or `~/.cache/mimi-base/` (version checked). GitHub is
  contacted only when none has the pinned release. Never commit the binary.
- Ports auto-skip when busy on the host (and on the Windows side under WSL).
  Pin them per worktree in `.env` (`VITE_PORT`, `PB_PORT`) if you want stable
  URLs; shell env wins.
- `MIMI_DEV_LOWMEM=1` in `.env` (or the shell) starts Vite with
  `RAYON_NUM_THREADS=1` if that is not already set. Rolldown's worker pool is
  most of the dev server's memory: `dev:all` peaks around 1.96GB with the
  default pool and 1.55GB with one thread, at the cost of roughly 10% on the
  first page load. Opt in on the machine that is short on RAM.
- `dev:all` prints the LAN URL for phone testing. PocketBase stays on loopback;
  Vite proxies `/api` and dev uses `VITE_POCKETBASE_URL=same-origin`.
- One PocketBase per checkout is enforced: a second `dev:all` in the same
  worktree reuses the running one and only picks another Vite port.
- Stop the servers (Ctrl-C) before `git worktree remove <path>`. `.env` and
  `pocketbase/pb_data/` are gitignored, so removing the directory is enough.
- **Remove a worktree as soon as its branch is merged into `master` and
  pushed** — do not wait for the user to ask. Stop its dev server, confirm the
  tree is clean and the branch is merged (`git branch --merged master`), then
  run `git worktree remove ../mimi-base-<topic>` and
  `git branch -d feat/<topic>`. Leave anything unmerged or dirty alone, and
  mention the cleanup in one line of your summary.

## Landing a worktree

`master` stays linear: a finished branch is rebased onto `master` and merged
with a fast-forward. Never merge `master` down into a feature branch, and
never create a merge commit.

```bash
# in the worktree
git fetch origin
git rebase origin/master

# in the primary checkout
git switch master
git merge --ff-only feat/<topic>
git push
```

- `--ff-only` is the enforcement: if it refuses, the branch is not on top of
  `master`. Rebase again; do not fall back to a merge commit.
- Re-run `bun run typecheck` and `bun run test` after the rebase — it replays
  each commit, so verify the final tree before it lands.
- Generated-file conflicts (`app/routeTree.gen.ts`, `bun.lock`) are resolved
  by taking `master`'s side and regenerating (`bun install`, then let the dev
  server rewrite the route tree); never hand-merge them.
- Never rebase `master`. Never rebase a branch that is pushed or checked out
  in another worktree: rebase rewrites commits, so that needs
  `--force-with-lease` and breaks anyone based on it.
- Squash fixups with `git rebase -i origin/master` before the final rebase so
  the linear history stays readable.
- With linear history there is no per-topic merge commit: back a topic out by
  reverting its range (`git revert <first>^..<last>`), not by hunting a merge
  SHA.
- Recommended once per clone: `git config merge.ff only` and
  `git config pull.rebase true`, so a plain merge or pull cannot create a
  merge commit by accident.
- Push `master` only when the user asks; the cleanup rule above applies once
  it is fast-forwarded and pushed.

## Update log

User-facing changes are recorded in two places **in the same commit**:

- `app/about/updates.ts` — what 关于 shows in the app. Only changes a user can
  notice; skip refactors, tooling and docs. Newest first, one entry per day
  (extend today's entry instead of adding a second), Chinese copy with no
  file paths or internal terms (`APP_SHA`, collection names, ...). Bullets go
  under `added` / `fixed` / `changed`.
    - Fill `summary` for every new entry: one sentence (≤ 45 chars) shown
      under the title. It is the collapsed card's only context, so write it
      as a benefit, not a list of internals.
    - Optionally add `highlight`: copy **one bullet verbatim** from the
      groups. It renders above them as 这次的重点 and is removed from its
      group, so don't write a paraphrased duplicate.
    - Optionally add `links` (`{ label, to }`) to jump into the feature that
      shipped (`/chat`, `/jizhang`, `/report`, ...). `to` is typed to the
      main app routes and must stay in-app.
    - Pages render as a timeline grouped by month; the newest entry opens by
      default and the section has 展开全部 / 收起全部. Media (screenshots,
      GIFs, video) is deliberately unsupported — keep it text-first.
- `CHANGELOG.md` — the developer-facing record. Add a bullet under the
  matching `###` heading in today's dated section (`## YYYY-MM-DD`), creating
  it above older sections if needed. Include internal work users won't notice.
  Both files describe the same batch; keep them consistent.

`app/about/updates.test.ts` checks the in-app log's shape (real dates,
newest-first, at least one bullet, summary length, `highlight` must match a
real bullet, links must be labelled in-app paths) and that every in-app date
has a matching `## YYYY-MM-DD` section in `CHANGELOG.md`. It cannot tell
whether you logged a change at all — that part is on you. Never claim a
feature the diff doesn't contain.

## Parallel sessions

Several agent sessions may run at once. The **primary checkout** (the first
entry of `git worktree list`) must stay clean: treat it as read-only. Every
writing session works in its own worktree.

If a task needs writes and `git rev-parse --show-toplevel` is the primary
checkout, create and move into a worktree yourself — do not ask the user to
start a new chat:

```bash
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install --frozen-lockfile
bun run install:server
cp .env.example .env
```

`--frozen-lockfile` stops the install from rewriting `bun.lock`; package
contents come from the shared Bun cache, so it is fast and needs no network
unless a dependency is actually new. `install:server` does the same for the
supervisor's own `pocketbase/package.json` (pdf.js + canvas), which the app
build deliberately does not install. Re-check `git rev-parse --show-toplevel`
before your first commit.

- Stop any dev server in the primary checkout before switching — otherwise it
  keeps regenerating `app/routeTree.gen.ts` in the old tree.
- If the primary checkout, or any tree you did not create, has uncommitted
  work, ask before touching it. Never `git reset --hard`, `git checkout .`,
  `git stash`, or `git clean` in a tree you don't own.
- One topic, one worktree, one branch. If the directory or branch already
  exists, pick a variant — never reuse it.
- Worktrees isolate files, not history. Land one by rebasing it onto `master`
  and fast-forwarding `master` (see Landing a worktree), one session at a
  time, then remove the merged worktree.

## Backend / data rules

- Use the singleton `pb` from `lib/pb.ts`; don't create another client.
- URL layout: PocketBase is mounted at `/db` (SDK base `<origin>/db`, admin
  dashboard `/db/_/`); hand-written Bun endpoints live under `/api/*` (AI
  `/api/ai/*`, feedback `/api/feedback/*`). Vite proxies `/db` to PocketBase
  and `/api` to the supervisor; production does the same (strip `/db` before
  PocketBase, exact `/db/sync` to the supervisor first). New Bun handlers go
  under `/api/*` and need no proxy change; `/feedback` stays the SPA route.
  `VITE_POCKETBASE_URL` may be a bare origin or end in `/db`; `lib/env.ts`
  normalizes it and never sends PocketBase's SDK to root `/api`.
- Collections: `users` (auth), `tou_xiang_circle`, `posts`, `comments`,
  `post_likes`, `comment_likes` (schema only, unused by the UI),
  `ji_zhang_biao`, `ji_zhang_category`, `study_progress`,
  `chat_conversations`, `chat_messages`, `chat_personas`, `chat_memories`,
  `chat_artifacts`, `dinner_options` (shared 晚餐抽奖机 menu),
  `feedback_reports` (问题反馈 / 功能建议); `tu_pian_xin_xi` is legacy (its rows
  were migrated into `posts`).
- Every data collection is auth-only (`@request.auth.id != ""`); keep `posts`
  that way. **This is deliberate, not a leak.** The product has exactly two
  accounts for one couple, sign-up is locked (`users.createRule = null` in
  `1792854446_updated_users.js`), and the shared feed / shared ledger _is_ the
  feature. Don't "fix" auth-only rules by owner-scoping posts or comments, and
  don't add a friends system. Scope today: `study_progress`,
  `ji_zhang_category`, `tou_xiang_circle` and all `chat_*` collections are
  owner-scoped; `feedback_reports` is owner-only for bug rows plus
  update/delete, but its list/view rule shares `kind = "feature"` rows with
  both accounts (`1795800000_share_feature_feedback.js`); `ji_zhang_biao` is
  shared for reads but owner-scoped for update/delete. If a third account is
  ever added, decide and migrate the per-collection scope _before_ that
  account exists — auth-only rules would expose every row to it.
  File fields are `protected`, so unauthenticated requests to `/api/files/...`
  return 404.
- All filters must be parameterized: `pb.filter("post_id = {:postId}", {...})`.
  Date literals use `pbDate(date)` (`YYYY-MM-DD HH:mm:ss.SSSZ`).
- File fields (`users.tou_xiang`, `tou_xiang_circle.image`, `posts.images`,
  `posts.videos`) store filenames, not URLs. They are protected, so build URLs
  with `getFileUrl` (or `getUserAvatarUrl` / `getUserCircleUrl`), which appends
  the short-lived token; the auth store refreshes it. Never call
  `pb.files.getURL` directly for these files — `<img>` cannot send the auth
  header, so a tokenless URL 404s. Feedback attachments are **not** PB files:
  `feedback_reports.attachments` only stores `{ name, url, size, type }`
  metadata pointing at GitHub release assets.
- Feedback is a three-step flow for both kinds: the client uploads attachments
  (`POST /api/feedback/upload`, multipart `files`, max 3 × 10MB, any MIME) to
  the `feedback-assets` GitHub prerelease, creates `feedback_reports`
  (`kind` bug/feature, `attachments` metadata JSON, optional
  `chat_conversations` relation for bugs), then POSTs `{ reportId }` to
  `/api/feedback/report`. Attaching an AI conversation starts in the chat
  thread's 反馈问题 menu (`/feedback?conversation=<id>`); the feedback page has
  no conversation picker. The Bun supervisor (`pocketbase/feedback.ts`)
  authenticates with the caller's PB token, re-reads the row with that token,
  and still requires `report.owner === caller` — the shared feature read rule
  lets the other account read a suggestion, never sync it. There is **no
  per-user submission cap** (two trusted accounts, and the report list offers
  a 重新同步 action); it opens a GitHub issue with the server-only
  `GITHUB_TOKEN` (`GITHUB_REPO`, optional `GITHUB_API_URL` /
  `GITHUB_UPLOADS_URL`). **Never** send the GitHub token or the PB token to the
  browser. Missing token/repo still accepts a text-only report with
  `200 { issue: null }` and the row stays `stored` (UI: 待同步), and the report
  card can retry it later; attachment uploads return 503 instead and no report
  row is created. GitHub failures set `status=failed` without losing the
  report. Bug issues are `[Bug]` + `bug`/`from-app`, and their body may include
  the last 20 console errors and a server-fetched transcript of the last 20
  chat messages / 10k chars. Feature issues are `[Feature]` +
  `enhancement`/`from-app`, never fetch a transcript, and their body is the
  idea plus inline attachment images/links. Retrying an already-synced report
  reuses its existing issue without another GitHub call. The feature tab's
  大家的建议 is shared; the bug tab's 我的反馈 stays owner-only. Realtime
  subscriptions are row-filtered by PocketBase, so the other account receives
  feature events only. Closing an issue happens on GitHub, so
  `POST /api/feedback/issue-state` (auth-only, max 50 report ids) re-reads the
  rows with the caller's token and syncs `issue_state` / `issue_state_checked`
  back onto them; only `issue_created` rows not already `closed` are refreshed
  (one-minute in-memory cache), and a stored `closed` is terminal — reopening
  the issue on GitHub does not flip the badge back. The badge paints from the
  persisted value, shows「已关闭」instead of「已建 Issue」, and a GitHub read
  failure leaves the stored label untouched. Writes use the `SUPERUSER_EMAIL` /
  `SUPERUSER_PASSWORD` already in `.env.prod` (dev: seeded `dev@mimi.local`)
  so shared suggestions persist for the non-owner; without it the caller's
  token only updates their own reports. Vite proxies `/api` (Bun) and
  `/db` (PocketBase); production routes `/api/*` to the supervisor and `/db/*`
  to PocketBase after stripping the prefix, while `/feedback` stays a client
  route.
- Avatar rings have two sources: `users.circle_preset` stores a built-in key
  from `components/TouXiang/presets.tsx` (`""` = default ring, `"none"` hides
  it), and `users.circle` points at an uploaded `tou_xiang_circle` row whose
  `owner` relation scopes create/update/delete. Render with
  `getUserRing(user)` so an uploaded ring wins over the preset.
- `author_id` / `user_id` relations have no DB default — always send them on
  create.
- `posts.like_count` / `comment_count` are denormalized and maintained by
  `pocketbase/pb_hooks/post_counters.pb.js` on like/comment create/delete. Do
  not bump them again on the client. The delete hook runs for cascaded replies
  too, so deleting a comment keeps the count accurate.
- Every `onRecord*Request` hook is **middleware**: the handler must call
  `e.next()` or PocketBase ends the request with `200` + an empty body and
  saves nothing, while the client SDK resolves it as success. That silently
  swallowed every new post for a while (see the `e.next()` regression test in
  `post_counters.test.js`); the create/update mutations also refuse a response
  without a record id.
- `comments.parent_id` supports unlimited reply depth. `buildCommentThreads`
  groups every descendant under its top-level comment and the UI shows
  `回复 @name`; the mutation sends `parent_id` (`""` for a top-level comment).
- `posts.images` holds up to 9 filenames; upload them as `FormData` fields in
  the same request that creates the post. `posts.videos` holds at most one
  MP4/WebM/MOV (50MB, protected) and is **mutually exclusive with images**:
  the composer only offers one kind at a time. Upload the video in the same
  create/update request; send `videos: ""` on update to clear it. Tweet-layout
  clips autoplay muted once 60% of the video is on screen (pausing off-screen
  and honouring `prefers-reduced-motion`); the other layouts never autoplay.
  The first frame comes from `#t=0.1` on the protected
  URL (`lib/postMedia.ts`). AI captions for video posts use the text hint
  only — never send video bytes to the model. `posts.media_meta` stores each
  image's and the video's intrinsic `{width, height}` positionally so the
  feed can reserve the real box before the protected files load; the composer
  fills it at upload (old rows without it measure on load). `posts.layout` is
  `moments` (朋友圈 square grid), `instagram` (full-bleed carousel) or
  `twitter` (compact timeline with the action row under the media), picked
  per post. `/posts` and `/photos` now redirect to `/home`.
- `ji_zhang_biao.category` is free text. It stores either a built-in key
  (`food`, `takeout`, `transport`, `shopping`, `home`, `fun`, `health`,
  `other`, defined in
  `app/routes/_protected/_main/jizhang/-categories.ts`) or the id of a
  `ji_zhang_category` row (the user's own categories). Resolve it through
  `useExpenseCategories().getCategory` / `getExpenseCategory(value, custom)` —
  unknown or deleted values render as 其他, and rows created before the field
  existed stay empty. Renaming a custom category is safe because rows point at
  its id; deleting one first clears those rows to `""` so 补全分类 can pick them
  up again. Never hardcode a new category in a migration's `values`: the field
  is no longer a select.
- `pb.authStore.record` has no `expand`; fetch the profile with
  `expand: "circle"` (see `lib/auth.tsx`).
- Schema changes go in a new committed migration under
  `pocketbase/pb_migrations/`. Never edit an applied migration. Runtime data
  (`pb_data/`) is gitignored.
- Local dev auto-creates the app test users (`test@mimi.local` and
  `test2@mimi.local`, both `mimi123456`) and the PocketBase dashboard
  superuser (`dev@mimi.local` / `mimi123456`) for `/_/` via
  `pocketbase/pb_hooks/dev_seed.pb.js`. All are only created when missing, so
  a changed password is never overwritten; reset a superuser with
  `./pocketbase superuser upsert <email> <password>` run from `pocketbase/`.
  The hook only runs when `server.ts` sets `MIMI_DEV=1` (dev, i.e. no
  `.env.prod`); prod deletes that var, so none of them is created there.
  The login page lists the two app accounts in dev (one click), any protected
  URL accepts `?dev=test` / `?dev=test2` to sign in as that account and then
  replaces the URL without the param, and the profile page's 开发账号 section
  switches between them in place (`lib/dev-accounts.ts`, `ensureDevSession` in
  `lib/auth.tsx`). `DEV_ACCOUNTS` is empty in a production build, so none of
  these entries appears. Documented in the root `README.md`.

## Frontend conventions

- `@/*` maps to the repo root; use it instead of deep relative imports.
- Formatting: `bun fmt` using `bunfig.toml` (4 spaces, double quotes, 80 cols,
  trailing commas, Tailwind class sorting, import sorting). Lint rules live in
  `biome.json`, which deliberately mirrors the old ESLint bar: the a11y,
  React-Compiler-era and pure-style rules stay off, `useExhaustiveDependencies`
  stays `warn` with `reportUnnecessaryDependencies: false`, and CSS is linted
  with `noDescendingSpecificity` / `noImportantStyles` / `noUnknownAtRules`
  off. `build/` and PocketBase scripts are ignored; `components/ui/` is linted
  like the rest of the app (see "Forked shadcn primitives"). `bun fmt` still
  skips it.
- Data fetching lives in colocated React Query hooks (`-data.ts(x)`). Define
  every key in `lib/query-keys.ts` (`qk.*`); per-user keys include the user id,
  and mutations invalidate the `qk.*.all` prefix. Don't import `queryClient`
  from `app/main` — use `useQueryClient()`.
- Auth: one store owns "who is signed in". `lib/auth-store.ts` holds the
  snapshot (`status` + `user`), PocketBase holds only the credential, and the
  profile is fetched with `expand: "circle"`. `lib/auth.tsx` creates the single
  instance and exposes it through `useAuth()` (`useSyncExternalStore`), so
  components re-render from the same value the router guards read. The router
  context is built once in `app/main.tsx` and never changes identity — auth
  updates must not re-create it. `useAuth().user` is nullable; protected
  screens call `useCurrentUser()`. Guards await `auth.waitForAuth()` and branch
  on `status` (`_protected.tsx`, `login.tsx`, the `jizhang` loader); it returns
  the settled snapshot, and `login()` resolves only after the profile is in
  the store. Login/sign-out bump the store's generation, so a profile read
  that started earlier can never overwrite the newer account. Don't add
  `router.invalidate()` effects to paper over auth loading.
- Post-login targets always go through `lib/redirect.ts` (`toLoginTarget`
  rejects `/login` and off-site values, `hrefWithoutDev` strips `?dev=`).
  A login URL used as its own redirect target nests on every render, so never
  build one by hand.
- Account switching is logout-based for real users: 个人资料 → 账号 → 退出登录
  goes to `/logout`, which clears the query cache and returns to `/login` (the
  next login lands on `/home`). Dev builds also show a 开发账号 section that
  switches between the seeded accounts in place; it replaces the session
  without an intermediate anonymous state.
- `vite.config.ts` enables `autoCodeSplitting`. Keep heavy feature data behind
  route imports (the study bank is its own chunk); don't import it from the
  app shell.
- AI features live in `app/ai/` and are app-wide: `AiProvider` is mounted in
  `_main.tsx`, not the study route. `client.ts` supports text, streaming, JSON,
  and vision (`visionMessage` + `imageToDataUrl` in `image.ts`, which downsizes
  to 1024px JPEG). Prompts are split by domain (`expense.ts`, `posts.ts`,
  `home.ts`, `study.ts`, `report.ts`); the study prompt helpers stay in
  `prompts.ts`.

    The site owns the only AI key; by design there is no BYOK path. The Bun
    supervisor (`pocketbase/server.ts`) mounts `pocketbase/ai-relay.ts` at
    `/api/ai/opencode/v1/chat/completions`, authenticates the caller's PocketBase
    token via `auth-refresh`, and streams the upstream SSE body back unchanged.
    General chat uses `POST /api/ai/chat/completions` + `GET /api/ai/models` instead:
    the model must be in the server allowlist (`chat-models.ts`, narrowed by
    `OPENCODE_CHAT_MODELS`), unknown ids get 400, text-only models lose
    `tools`, non-vision models reject image parts, and `reasoning_effort` is
    validated against the model's `thinkingLevels`. The legacy path keeps
    forcing `OPENCODE_MODEL`.
    `OPENCODE_API_KEY` / `OPENCODE_MODEL` / `AI_DAILY_REQUESTS_PER_USER` come
    from `.env.prod` (dev: `.env`); the key never reaches the browser,
    PocketBase, or the logs, and `client.ts` only sends the PB token plus
    `x-opencode-session`. Only notification/local-budget prefs live in
    `localStorage` (`mimi:ai:v1`, legacy fallback); old saved API keys are
    scrubbed on load. Generated content is cached under `mimi:ai-cache:v1:*`
    keyed by `AI_MODEL` (`constants.ts`). Dev: `dev:all` picks a free
    `SUPERVISOR_PORT` and Vite proxies `/api` to it; the supervisor keeps
    `opencode.ai` out of the dev proxy env. Prod: the reverse proxy routes
    `/api/*` to :9001 with buffering off (`X-Accel-Buffering: no` is set too),
    and the Vercel build derives the API origin from `VITE_POCKETBASE_URL`.
    The feedback endpoints are `POST /api/feedback/upload` (attachments),
    `POST /api/feedback/report` and `POST /api/feedback/issue-state` (syncs
    the GitHub state onto the report row) on the same supervisor, so the
    `/api/*` rule covers them;
    `/feedback` itself stays the SPA route. `GITHUB_TOKEN` /
    `GITHUB_REPO` / `GITHUB_API_URL` / `GITHUB_UPLOADS_URL` live in `.env.prod`
    (dev: `.env`); `server.ts` carries them across a respawn. Video posts use
    `POST /api/video/compress` (auth-only, multipart `file`, max 50MB): the
    supervisor runs the optional `ffmpeg` binary (or `FFMPEG_PATH`) to return a
    ≤1280px H.264/AAC MP4, and the client uploads that to PocketBase. Files
    under 8MB skip the call; missing ffmpeg/failure/not-smaller answers make
    the client publish the original instead, so a post never fails for lack of
    compression. The endpoint never stores the original.

- Long AI requests go through `AiTasksProvider` (`app/ai/tasks.tsx`, mounted by
  `AiContext`): closing a sheet or changing pages no longer aborts them. Use
  `runTask({ key, group, cacheKey, title, run })` and let the store own the
  `AbortController`; never abort on unmount/close. Successful results are
  written to `cacheKey` and appear in the task center (bottom-left pill +
  sonner toast); `attend(group)` marks a task as watched while its page/panel
  is open so it does not double-notify. Panels that can close mid-flight must
  restore the task when they reopen: use `decideAiRestore` from
  `app/ai/restore.ts` (running task first, then local state → store result →
  cache) instead of hand-rolling the checks, so a finished result never
  becomes unreachable. System notifications are opt-in via
  `AiSettings.notify` and only fire while the page is hidden. This is
  client-side background: reloading or fully closing the app still stops
  in-flight requests, because the task store lives in memory.
- General chat (`app/chat/`, `/chat`): assistant-ui primitives +
  `useExternalStoreRuntime`; messages persist in `chat_messages` as content
  parts. A run loops up to 6 model rounds while it calls `sandbox_*` tools.
  Run state (running / live draft / optimistic rows / `AbortController` /
  sandbox files / watchers) lives in `app/chat/run-store.ts`, keyed by
  conversation id — **not** in `useChatSession` component state. Leaving the
  thread (back gesture, bottom nav) keeps the loop and tool calls going;
  re-entering re-attaches and refuses a second send until the run ends. A
  pending `ask_user` carries its `conversationId` and survives navigation, so
  only stop/logout cancels it. The sandbox runs **Python or JavaScript on the
  server** in a Docker container (one image per language, selected by
  `sandbox_run.language`):
  read-only root, non-root user, all capabilities dropped, PID/memory/CPU
  limits, 60s wall clock, JSON on stdin (no code in argv), and the dedicated
  `mimi-sandbox` network whose egress firewall allows only public
  DNS/HTTP(S). It has no mounts, no host networking and no `pb_data` / env
  secrets. `pocketbase/sandbox/` owns the runner, Dockerfile and firewall.
  Dev (no Docker in WSL) uses a direct `python3`/`node` subprocess; that
  fallback is not isolated and must never be used in production. Don't add
  host mounts, `--network host`, a Docker socket, or secrets to the container
  without re-evaluating prompt injection against the AI key and `pb_data`.
  `ask_user` is client-side: it pauses the tool loop, shows the inline panel
  (text/choice/confirm/location/expense), and resolves the tool result so the
  same run continues. Location is a **city-only IP estimate**: the panel calls
  `GET /api/ai/geo/ip` (`pocketbase/geo-ip.ts`, bundled `ip2region` data) only
  after the user taps 自动识别城市, and the estimate is shown for confirmation
  before it reaches the model. Never resolve coordinates, never geolocate a
  request without that explicit tap, and never inject IP-derived location
  silently. `log_expense` uses the same pause: the model's draft is only
  written after the user taps 「记下」, and the create still goes through the
  owner-bound PB rule.
- Gen UI (`show_chart` + `render_ui`) is client-side and data-only.
  `show_chart` draws one bar/line/pie with a validated `style`
  (`palette` / `donut` / `legend` / `showValues`) using the `--chart-1..6`
  theme tokens. `render_ui` composes a **display-only** card from a whitelist
  of blocks (`app/chat/ui-spec.ts`: text / metrics / list / table / progress /
  badges / chart / divider; max 12 blocks and a 12k serialized spec). There is
  no HTML/CSS/JS, no remote URLs, and no buttons/forms/links. Both renderers
  map enum values to fixed literal theme-token classes (`-chart-card.tsx`,
  `-ui-card.tsx`) so Tailwind emits them and dark mode works. Never accept
  free-form Tailwind classes, event handlers or external content on this path.
- Chat data tools (`/api/ai/tools/{expenses,posts,comments,memory,url}` in
  `pocketbase/ai-tools.ts`) are the only way the model reads site data, and
  **the server, not the persona prompt, is the security boundary**: the relay
  authenticates, rate-limits (30/min) and quotas (200/day) them, scopes rows
  with explicit PB filters (ledger/posts/comments are shared-scope on purpose
  — they match the app's screens; `chat_memories` is owner-only with PB rules
  as the backstop), and `read_url` resolves DNS and refuses private/reserved
  hosts and redirects. `comments` reads recent comment rows (optional
  `post_id` / `query` / `author`, capped `limit`, truncated text) with the
  author, post context and parent author expanded. The system prompt tells the
  model tool output is data, not instructions — keep that line when editing
  `app/chat/prompt.ts`. Memories (`chat_memories`) are injected into every
  run's system prompt (top 30) and managed in the chat list header's
  「AI 的记忆」 sheet.
- Built-in personas (`app/chat/personas.ts`, shown in the UI as 应用场景) are
  日常对话 / 写作润色 / 英语学习 / 基地管家, each with `starters` for the
  empty thread. A conversation snapshots persona name+prompt at creation, so
  removing or editing a built-in never rewrites old chats. Personas are
  prompts only — never gate real capabilities on them.
- Other chat affordances: conversation search/filter/pin on the list page,
  per-message edit-and-resend (`onEdit`), fork-into-new-conversation,
  one-off retry with another model, Markdown export (header), document
  attachments, pick-images-from-posts, PWA share target (`/share`, GET
  params → composer draft), and read-aloud via the browser speech adapter.
  Code blocks highlight with a lazy Shiki chunk (`app/chat/highlighter.ts`,
  JS regex engine, no wasm). Attachments are uploaded raw to
  `POST /api/ai/files` and read on the relay (`pocketbase/ai-files.ts`): pdf.js
  runs **server-side** with the CMaps/standard fonts from
  `pocketbase/node_modules` (deps live in `pocketbase/package.json`, not the
  app's; without the CMaps Chinese PDFs extract as an empty string), text
  becomes a fenced part, and a scanned PDF's first pages are rendered with
  `@napi-rs/canvas` to JPEG image parts for a vision model. The phone never
  loads pdf.js or CMaps; uploads are not persisted. Caps live in
  `lib/chat-files.ts` (30MB, 50k chars, 20 text pages, 4 page images).
- Chat artifacts (files the assistant hands the user): text files (HTML,
  Markdown, CSV, JSON, SVG, code) stay in `chat_conversations.sandbox_files`
  and an artifact part references the path; binary raster images come back
  **once** in the `sandbox_run` response (`artifacts`, base64; the container
  is stateless, so a later call cannot recover them), are uploaded to
  `chat_artifacts` (owner-scoped, protected `file`, `message` cascade), and
  the part stores only the record id + filename. `send_file` surfaces a text
  file; `sandbox.download(url, path)` writes a public image into the sandbox.
  The card and full-screen viewer live in `-artifact-viewer.tsx`; HTML/SVG
  must render in `<iframe sandbox="">` (no `allow-same-origin`, no scripts)
  with the injected `default-src 'none'` CSP — **never** inline or in a
  Shadow DOM, which is not a security boundary (same origin, same
  `localStorage` / PB token).
- AI entry points: 聊天, 记账 (natural-language + receipt parse, monthly review,
  category backfill), 动态 composer captions, Home (去年今天 inline in the
  feed; the daily line is computed locally), Study (wrong-answer overview,
  targeted drill, sprint plan), the year report at `/report`, and AI polish in
  问题反馈 (bug: title/symptom/reproduction) and 功能建议 (want/why/how). A 503
  keeps the original text and the form still submits. Data sent to the provider
  is only what the feature builds locally; nothing AI-related is written back
  to PocketBase except the user-confirmed expense rows/categories.
- Adding a page: create `app/routes/_protected/_main/<name>/index.tsx` with
  `createFileRoute("/_protected/_main/<name>/")`, let the dev server regenerate
  `routeTree.gen.ts`, then add a nav entry in `components/NavButtons/index.tsx`.
- Style with Tailwind + `components/ui` primitives + `cn()` from
  `lib/utils.ts`. There are no CSS modules; the nav uses lucide icons.
- `hover:` styles only reach devices that can hover — v4 emits them behind
  `@media (hover: hover)` by default. A touch tap latches `:hover` until the
  next tap, so a hover-only affordance looks stuck on a phone; use `active:`
  or state classes for touch feedback.
- Theme tokens live in `globals.css` (`:root` + `.dark`). Prefer semantic
  classes (`bg-card`, `text-muted-foreground`, `border-border`, `shadow-soft`)
  over raw colors so both schemes keep working. `ThemeProvider` is in
  `lib/theme.tsx`; the nav toggle persists the choice under `mimi-theme`.
- Use `toastPromise` for async user actions (loading/success/error toasts).
- Overlays must close on the mobile back gesture (edge swipe / hardware back)
  instead of navigating the page behind them away. `lib/useBackDismiss.ts`
  provides this, and `Dialog`, `Sheet`, `Drawer` and `AiSheet` call it for you.
  Hand-rolled full-screen surfaces (e.g. `QuizRunner`) must call it themselves.
  It keeps one shared history entry while any overlay is open and unwinds
  nested overlays one at a time. `AiSheet` is a Radix dialog on purpose: a
  plain `div` over a `Drawer`/`Dialog` is "outside" for them, so tapping any
  button in the AI panel also closes the sheet underneath (e.g. the new-post
  composer vanishing when you pick a caption).
- The shell assumes `100dvh`; keep page scrolling inside the `_main` outlet.
- Accessibility: `globals.css` provides a global `:focus-visible` outline and
  disables decorative animation under `prefers-reduced-motion`. Don't add
  `outline-none` to interactive elements; keep icon-only controls labelled.
  `_main.tsx` ships a skip link to `#main-content`.

## Forked shadcn primitives

`components/ui/` is a **fork**, not pristine `shadcn add` output. Five files
carry customizations that must survive any future `shadcn add` / `init` /
primitives refresh:

- `dialog.tsx` — the `Dialog` root calls `useBackDismiss`; `DialogContent`
  adds `overlayClassName`, `showCloseButton` and `mobileSheet` (bottom-sheet
  layout below `sm`, centered dialog above; used by `ConfirmDialog`).
- `sheet.tsx` — the `Sheet` root calls `useBackDismiss`.
- `drawer.tsx` — the `Drawer` root calls `useBackDismiss` and defaults
  `repositionInputs={false}` (our own keyboard handling sizes the sheet).
- `sonner.tsx` — theme-aware `Toaster` driven by `useTheme()`.
- `form.tsx` — `FormItem` uses `[&>*+*]:mt-2` instead of `space-y-2`. v4's
  `space-y-*` puts the gap on the preceding sibling, which is the inline
  `<label>` where vertical margins are ignored; the arbitrary variant puts it
  back on the input and keeps the v3 spacing.

`components.json` records the fork (see its `x-mimi-fork` note), and Biome
lint-checks `components/ui/` like the rest of the app. **Do not
regenerate these files** with the shadcn CLI without re-applying the
customizations above (or moving them into `components/overlays/` wrappers and
re-pointing every importer). The customizations live inside the primitives
today because all app imports point at `@/components/ui/*`; a full wrapper
extraction would also require touching importers outside the UI layer.

Tailwind is **v4 and CSS-first**: there is no `tailwind.config.js`. The theme
lives in `globals.css` (`@theme inline` over the HSL triplets plus the
`--radius` scale), dark mode is `@custom-variant dark (&:is(.dark *))`,
`tw-animate-css` replaces `tailwindcss-animate`, and `@source` pins the content
roots to `index.html` + `app/` + `components/` (the old `content` globs). Vite
loads it through `@tailwindcss/vite`; there is no PostCSS config. Utilities
keep the v3 look: `* { @apply border-border }` neutralizes v4's
`currentColor` border default, and the `rounded-*` names still map to the
app's own `--radius` scale (not v4's default one). The utilities v4 renamed
are migrated — `outline-hidden`, `shadow-xs`, `bg-linear-to-*`, and `!` as a
**suffix** (`text-destructive!`).

## Gotchas

- Router context (`auth`, `queryClient`) is injected in `app/main.tsx`; add new
  root context keys in both the router and `__root.tsx`.
- Typechecking is `bun check` only: `bun run typecheck` runs it for the app and
  again inside `pocketbase/` for the server project. There is no separate `tsc`
  script or hook step — a differential run of `tsc --noEmit` against
  `bun check` over this repo (and over a hand-written set of inference /
  narrowing cases) produced the same diagnostics, so don't reintroduce one.
  That is also why the `typescript` package is gone: nothing loads it any more
  (Vite resolves tsconfig `paths` itself, the router plugin does not need it). The root `tsconfig.json`
  excludes `pocketbase/`, so `bun run build` on Vercel/CI does not need the
  server's own deps. Keep `"types": ["bun"]` and no `baseUrl` in
  `tsconfig.json`.
- Run `bun run setup:hooks` once per clone to enable `.githooks/pre-commit`,
  which runs `bun fmt --staged`, `bun run typecheck`, `bun run test`,
  `bun run lint`, and `bun run format:check`.
- `APP_VERSION` and `APP_SHA` are Vite `define` globals (declared in
  `vite-env.d.ts`), not environment variables. The app shows the build sha,
  not a version number: there is no release-bump step.
- `pb.autoCancellation(false)` in `lib/pb.ts` is intentional: the feed and like
  queries would otherwise abort each other.
- PocketBase records use `created` / `updated`; app types map them (e.g.
  `createdAt`).
- Build output is `build/` (not `dist`). `vercel.json` rewrites all paths to
  `/` for SPA routing. Vercel and the self-hosted PocketBase serve **two
  separate builds**: Vercel builds from the repo, while `deploy-spa.yml`
  builds with `VITE_POCKETBASE_URL=same-origin` and POSTs its own tarball to
  `/spa/publish`; PB serves that copy from `build/` via `--publicDir` in prod.
  Both hosts run at once.
- PWA: `public/sw.js` is hand-written with a `VERSION` constant; bump it when
  caching behavior changes. It is registered only in production builds by
  `lib/service-worker.ts`. New workers wait for `SKIP_WAITING`; the app shows a
  "有新版本可用" toast and reloads only after the user accepts. Navigation
  failures fall back to the cached shell, then to an inline offline page.
- `lib/env.ts` validates `VITE_POCKETBASE_URL` at module load — a missing env
  var crashes the app immediately.
- Default branch is `master`. Pushing `pocketbase/**` to `master` triggers
  `.github/workflows/deploy-db.yml` → `/db/sync` (git pull,
  `bun install --frozen-lockfile --production` in `pocketbase/`, stop PB,
  snapshot `pb_data` while it is down, restart; migrations apply on restart
  even with automigrate off).
  Frontend paths trigger `.github/workflows/deploy-spa.yml`, which builds with
  `VITE_POCKETBASE_URL=same-origin` and POSTs the tarball to `/spa/publish`;
  PB serves it from `build/` with no restart (`build.old` keeps one
  generation, `/spa/rollback` swaps back).
- `pocketbase/server.ts` must stay inside `pocketbase/`: the binary resolves
  `pb_migrations` and `pb_hooks` relative to the data dir.
- Never commit `.env`, `.env.prod`, `pocketbase/pb_data/`, or `tmp/`.
