# AGENTS.md

## What this repo is

`mimi-base` ("秘密基地") is a personal, mobile-first PWA for sharing photos,
posts, and expense records. Frontend: React 18 + Vite + TypeScript, TanStack
Router (file-based routes) + React Query, Tailwind + shadcn/ui. Backend:
PocketBase (SQLite + file uploads) run by a Bun supervisor. UI copy is
Chinese; keep that style when adding user-facing text.

## Layout

- `app/main.tsx` — entry: QueryClient, router, `AuthProvider`, prod-only SW
  registration.
- `app/routes/` — TanStack Router file routes. `app/routeTree.gen.ts` is
  generated by the Vite plugin; never hand-edit it.
    - `__root.tsx` root layout; `_protected.tsx` auth gate; `_protected/_main.tsx`
      app shell (scroll area + bottom `NavButtons`).
    - `_protected/_main/{home,posts,chat,jizhang,study,profile,report,photos}/`
      feature pages; `photos/` now redirects to `/posts`. `chat/` has an index
      (conversation list) and `$conversationId.tsx` (thread).
    - Files starting with `-` (`-data.tsx`, `-comments.ts`, `-components/`) are
      colocated helpers, not routes.
- `components/ui/` — shadcn/ui primitives. These are a **fork** (see
  "Forked shadcn primitives" below): `dialog.tsx`, `sheet.tsx`, `drawer.tsx`,
  `sonner.tsx` carry hand-applied customizations and must not be regenerated.
  ESLint now checks this directory (scoped override in `eslint.config.js`);
  `bun fmt` still skips it.
- `components/` — app components (`NavButtons`, `TouXiang`, `LoadingPage`).
- `app/chat/` — general-chat domain logic: `api.ts` (relay URLs and allowlist
  fetch), `stream.ts` and `sse.ts` (streaming/tool-call parsing), `prompt.ts`,
  `personas.ts`, `title.ts`, `records.ts`, and `tools.ts` (the server-side
  sandbox itself lives in `pocketbase/sandbox/`).
- `lib/` — `pb.ts` (PocketBase singleton + URL/date helpers), `auth.tsx`,
  `env.ts`, `toast-promise.ts`, `date.ts`, image picker/compressor.
- `hooks/` — shared hooks.
- `pocketbase/` — server side: `server.ts` supervisor, `pb_migrations/`
  (schema), `pb_hooks/` (JSVM counters). Read `pocketbase/README.md` before
  touching deploys or the server.
- `public/` — PWA `sw.js`, `manifest.json`, images.
- `scripts/server-setup.sh` — fresh-server bootstrap. `scripts/dev.ts` backs
  `bun run dev:all` on Linux, WSL2 and plain Windows. Under WSL it also runs
  `scripts/lan-proxy.mjs` with the Windows node to forward the Vite port to the
  VM (no admin or portproxy required). PocketBase stays on loopback; Vite
  proxies `/api` and dev runs with `VITE_POCKETBASE_URL=same-origin`.
  `tmp/` is gitignored scratch (do not commit).

## Commands

```bash
bun install
cp .env.example .env      # VITE_POCKETBASE_URL=http://127.0.0.1:8090
bun run db                # PocketBase on 127.0.0.1:8090 (admin at /_/)
bun run dev               # Vite on :3000 (VITE_PORT=3001 to change)
bun run dev:all           # both, always LAN-exposed (prints the phone URL)
                          # skips busy ports (WSL + Windows) and reads
                          # VITE_PORT/PB_PORT from .env; one instance per
                          # worktree is safe to run side by side
bun run build             # vite build + bun check
bun run test              # bun test (whole repo; pure logic, no server needed)
bun run typecheck         # bun check (Bun built-in typechecker)
bun run typecheck:tsc     # tsc --noEmit (typescript@^5.6.3, also in hook)
bun run lint              # eslint (flat config)
bun run format            # bun fmt
bun run format:check      # bun fmt --check
bun run setup:hooks       # enable .githooks/pre-commit once per clone
```

Formatting is Bun's native formatter (`bunfig.toml`), linting is the ESLint
flat config (`eslint.config.js`), and typechecking runs both `bun check` and
`tsc --noEmit`. There is no `bun lint`; don't reintroduce Prettier or
`.eslintrc`. Unit tests use Bun's built-in runner and cover pure logic only;
`bun test` scans the whole repo. Verify UI changes with `bun run build` and the
dev server.

## Worktrees

Do feature work in its own worktree so `master` stays deployable.

```bash
cd <repo>
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install
cp .env.example .env
bun run dev:all
```

- Convention: directory `../mimi-base-<topic>`, branch `feat/<topic>`.
- Run git from the environment that owns the checkout (native shell for a
  native clone, inside WSL for a WSL checkout).
- Each worktree has its own `pocketbase/pb_data/` (own database) and its own
  `dev:all` stack; they can run side by side.
- The PocketBase binary is copied automatically from a registered worktree, a
  sibling checkout, or `~/.cache/mimi-base/` (version checked). GitHub is
  contacted only when none has the pinned release. Never commit the binary.
- Ports auto-skip when busy on the host (and on the Windows side under WSL).
  Pin them per worktree in `.env` (`VITE_PORT`, `PB_PORT`) if you want stable
  URLs; shell env wins.
- `dev:all` prints the LAN URL for phone testing. PocketBase stays on loopback;
  Vite proxies `/api` and dev uses `VITE_POCKETBASE_URL=same-origin`.
- One PocketBase per checkout is enforced: a second `dev:all` in the same
  worktree reuses the running one and only picks another Vite port.
- Stop the servers (Ctrl-C) before `git worktree remove <path>`. `.env` and
  `pocketbase/pb_data/` are gitignored, so removing the directory is enough.
- **Remove a worktree as soon as its branch is merged into `master` and
  pushed** — do not wait for the user to ask. Stop its dev server, confirm the
  tree is clean and the branch is merged (`git branch --merged master`), then
  run `git worktree remove ../mimi-base-<topic>` and
  `git branch -d feat/<topic>`. Leave anything unmerged or dirty alone, and
  mention the cleanup in one line of your summary.

## Landing a worktree

`master` stays linear: a finished branch is rebased onto `master` and merged
with a fast-forward. Never merge `master` down into a feature branch, and
never create a merge commit.

```bash
# in the worktree
git fetch origin
git rebase origin/master

# in the primary checkout
git switch master
git merge --ff-only feat/<topic>
git push
```

- `--ff-only` is the enforcement: if it refuses, the branch is not on top of
  `master`. Rebase again; do not fall back to a merge commit.
- Re-run `bun run typecheck` and `bun run test` after the rebase — it replays
  each commit, so verify the final tree before it lands.
- Generated-file conflicts (`app/routeTree.gen.ts`, `bun.lock`) are resolved
  by taking `master`'s side and regenerating (`bun install`, then let the dev
  server rewrite the route tree); never hand-merge them.
- Never rebase `master`. Never rebase a branch that is pushed or checked out
  in another worktree: rebase rewrites commits, so that needs
  `--force-with-lease` and breaks anyone based on it.
- Squash fixups with `git rebase -i origin/master` before the final rebase so
  the linear history stays readable.
- With linear history there is no per-topic merge commit: back a topic out by
  reverting its range (`git revert <first>^..<last>`), not by hunting a merge
  SHA.
- Recommended once per clone: `git config merge.ff only` and
  `git config pull.rebase true`, so a plain merge or pull cannot create a
  merge commit by accident.
- Push `master` only when the user asks; the cleanup rule above applies once
  it is fast-forwarded and pushed.

## Update log

User-facing changes are recorded in two places **in the same commit**:

- `app/about/updates.ts` — what 关于 shows in the app. Only changes a user can
  notice; skip refactors, tooling and docs. Newest first, one entry per day
  (extend today's entry instead of adding a second), Chinese copy with no
  file paths or internal terms (`APP_SHA`, collection names, ...). Bullets go
  under `added` / `fixed` / `changed`.
- `CHANGELOG.md` — the developer-facing record. Add a bullet under the
  matching `###` heading in today's dated section (`## YYYY-MM-DD`), creating
  it above older sections if needed. Include internal work users won't notice.
  Both files describe the same batch; keep them consistent.

`app/about/updates.test.ts` checks the in-app log's shape (real dates,
newest-first, at least one bullet) and that every in-app date has a matching
`## YYYY-MM-DD` section in `CHANGELOG.md`. It cannot tell whether you logged a
change at all — that part is on you. Never claim a feature the diff doesn't
contain.

## Parallel sessions

Several agent sessions may run at once. The **primary checkout** (the first
entry of `git worktree list`) must stay clean: treat it as read-only. Every
writing session works in its own worktree.

If a task needs writes and `git rev-parse --show-toplevel` is the primary
checkout, create and move into a worktree yourself — do not ask the user to
start a new chat:

```bash
git worktree add -b feat/<topic> ../mimi-base-<topic> master
cd ../mimi-base-<topic>
bun install --frozen-lockfile
cp .env.example .env
```

`--frozen-lockfile` stops the install from rewriting `bun.lock`; package
contents come from the shared Bun cache, so it is fast and needs no network
unless a dependency is actually new. Re-check `git rev-parse --show-toplevel`
before your first commit.

- Stop any dev server in the primary checkout before switching — otherwise it
  keeps regenerating `app/routeTree.gen.ts` in the old tree.
- If the primary checkout, or any tree you did not create, has uncommitted
  work, ask before touching it. Never `git reset --hard`, `git checkout .`,
  `git stash`, or `git clean` in a tree you don't own.
- One topic, one worktree, one branch. If the directory or branch already
  exists, pick a variant — never reuse it.
- Worktrees isolate files, not history. Land one by rebasing it onto `master`
  and fast-forwarding `master` (see Landing a worktree), one session at a
  time, then remove the merged worktree.

## Backend / data rules

- Use the singleton `pb` from `lib/pb.ts`; don't create another client.
- Collections: `users` (auth), `tou_xiang_circle`, `posts`, `comments`,
  `post_likes`, `comment_likes` (schema only, unused by the UI),
  `ji_zhang_biao`, `ji_zhang_category`, `study_progress`,
  `chat_conversations`, `chat_messages`, `chat_personas`; `tu_pian_xin_xi` is
  legacy (its rows were migrated into `posts`).
- Every data collection is auth-only (`@request.auth.id != ""`); keep `posts`
  that way. **This is deliberate, not a leak.** The product has exactly two
  accounts for one couple, sign-up is locked (`users.createRule = null` in
  `1792854446_updated_users.js`), and the shared feed / shared ledger _is_ the
  feature. Don't "fix" auth-only rules by owner-scoping posts or comments, and
  don't add a friends system. Scope today: `study_progress`,
  `ji_zhang_category`, `tou_xiang_circle` and all three `chat_*` collections
  are owner-scoped; `ji_zhang_biao` is shared for reads but owner-scoped for
  update/delete. If a third account is ever added, decide and migrate the
  per-collection scope _before_ that account exists — auth-only rules would
  expose every row to it.
  File fields are `protected`, so unauthenticated requests to `/api/files/...`
  return 404.
- All filters must be parameterized: `pb.filter("post_id = {:postId}", {...})`.
  Date literals use `pbDate(date)` (`YYYY-MM-DD HH:mm:ss.SSSZ`).
- File fields (`users.tou_xiang`, `tou_xiang_circle.image`, `posts.images`)
  store filenames, not URLs. They are protected, so build URLs with
  `getFileUrl` (or `getUserAvatarUrl` / `getUserCircleUrl`), which appends the
  short-lived token; `AuthProvider` refreshes it. Never call
  `pb.files.getURL` directly for these files — `<img>` cannot send the auth
  header, so a tokenless URL 404s.
- Avatar rings have two sources: `users.circle_preset` stores a built-in key
  from `components/TouXiang/presets.tsx` (`""` = default ring, `"none"` hides
  it), and `users.circle` points at an uploaded `tou_xiang_circle` row whose
  `owner` relation scopes create/update/delete. Render with
  `getUserRing(user)` so an uploaded ring wins over the preset.
- `author_id` / `user_id` relations have no DB default — always send them on
  create.
- `posts.like_count` / `comment_count` are denormalized and maintained by
  `pocketbase/pb_hooks/post_counters.pb.js` on like/comment create/delete. Do
  not bump them again on the client. The delete hook runs for cascaded replies
  too, so deleting a comment keeps the count accurate.
- Every `onRecord*Request` hook is **middleware**: the handler must call
  `e.next()` or PocketBase ends the request with `200` + an empty body and
  saves nothing, while the client SDK resolves it as success. That silently
  swallowed every new post for a while (see the `e.next()` regression test in
  `post_counters.test.js`); the create/update mutations also refuse a response
  without a record id.
- `comments.parent_id` supports unlimited reply depth. `buildCommentThreads`
  groups every descendant under its top-level comment and the UI shows
  `回复 @name`; the mutation sends `parent_id` (`""` for a top-level comment).
- `posts.images` holds up to 9 filenames; upload them as `FormData` fields in
  the same request that creates the post. `posts.layout` is `moments`
  (朋友圈 square grid) or `instagram` (full-bleed carousel), picked per post.
  `/photos` now redirects to `/posts`.
- `ji_zhang_biao.category` is free text. It stores either a built-in key
  (`food`, `takeout`, `transport`, `shopping`, `home`, `fun`, `health`,
  `other`, defined in
  `app/routes/_protected/_main/jizhang/-categories.ts`) or the id of a
  `ji_zhang_category` row (the user's own categories). Resolve it through
  `useExpenseCategories().getCategory` / `getExpenseCategory(value, custom)` —
  unknown or deleted values render as 其他, and rows created before the field
  existed stay empty. Renaming a custom category is safe because rows point at
  its id; deleting one first clears those rows to `""` so 补全分类 can pick them
  up again. Never hardcode a new category in a migration's `values`: the field
  is no longer a select.
- `pb.authStore.record` has no `expand`; fetch the profile with
  `expand: "circle"` (see `lib/auth.tsx`).
- Schema changes go in a new committed migration under
  `pocketbase/pb_migrations/`. Never edit an applied migration. Runtime data
  (`pb_data/`) is gitignored.
- Local dev auto-creates two accounts via
  `pocketbase/pb_hooks/dev_seed.pb.js`: the app test user
  (`test@mimi.local` / `mimi123456`) and the PocketBase dashboard superuser
  (`dev@mimi.local` / `mimi123456`) for `/_/`. Both are only created when
  missing, so a changed password is never overwritten; reset it with
  `./pocketbase superuser upsert <email> <password>` run from `pocketbase/`.
  The hook only runs when `server.ts` sets `MIMI_DEV=1` (dev, i.e. no
  `.env.prod`); prod deletes that var, so neither account is created there.
  Documented in the root `README.md`.

## Frontend conventions

- `@/*` maps to the repo root; use it instead of deep relative imports.
- Formatting: `bun fmt` using `bunfig.toml` (4 spaces, double quotes, 80 cols,
  trailing commas, Tailwind class sorting). Import order is owned by ESLint;
  keep `sortImports = false`. Lint rules live in the flat `eslint.config.js`.
  `build/` and PocketBase scripts are ignored by ESLint; `components/ui/` is
  checked via a scoped override (see "Forked shadcn primitives"). `bun fmt`
  still skips it.
- Data fetching lives in colocated React Query hooks (`-data.ts(x)`). Define
  every key in `lib/query-keys.ts` (`qk.*`); per-user keys include the user id,
  and mutations invalidate the `qk.*.all` prefix. Don't import `queryClient`
  from `app/main` — use `useQueryClient()`.
- Auth: `useAuth().user` is nullable. Protected screens call
  `useCurrentUser()`; route guards await `auth.waitForAuth()` and branch on
  `status` (`_protected.tsx`, `login.tsx`). Don't add `router.invalidate()`
  effects to paper over auth loading.
- `vite.config.ts` enables `autoCodeSplitting`. Keep heavy feature data behind
  route imports (the study bank is its own chunk); don't import it from the
  app shell.
- AI features live in `app/ai/` and are app-wide: `AiProvider` is mounted in
  `_main.tsx`, not the study route. `client.ts` supports text, streaming, JSON,
  and vision (`visionMessage` + `imageToDataUrl` in `image.ts`, which downsizes
  to 1024px JPEG). Prompts are split by domain (`expense.ts`, `posts.ts`,
  `home.ts`, `study.ts`, `report.ts`); the study prompt helpers stay in
  `prompts.ts`.

    The site owns the only AI key; by design there is no BYOK path. The Bun
    supervisor (`pocketbase/server.ts`) mounts `pocketbase/ai-relay.ts` at
    `/ai/opencode/v1/chat/completions`, authenticates the caller's PocketBase
    token via `auth-refresh`, and streams the upstream SSE body back unchanged.
    General chat uses `POST /ai/chat/completions` + `GET /ai/models` instead:
    the model must be in the server allowlist (`chat-models.ts`, narrowed by
    `OPENCODE_CHAT_MODELS`), unknown ids get 400, text-only models lose
    `tools`, non-vision models reject image parts, and `reasoning_effort` is
    validated against the model's `thinkingLevels`. The legacy path keeps
    forcing `OPENCODE_MODEL`.
    `OPENCODE_API_KEY` / `OPENCODE_MODEL` / `AI_DAILY_REQUESTS_PER_USER` come
    from `.env.prod` (dev: `.env`); the key never reaches the browser,
    PocketBase, or the logs, and `client.ts` only sends the PB token plus
    `x-opencode-session`. Only notification/local-budget prefs live in
    `localStorage` (`mimi:ai:v1`, legacy fallback); old saved API keys are
    scrubbed on load. Generated content is cached under `mimi:ai-cache:v1:*`
    keyed by `AI_MODEL` (`constants.ts`). Dev: `dev:all` picks a free
    `SUPERVISOR_PORT` and Vite proxies `/ai` to it; the supervisor keeps
    `opencode.ai` out of the dev proxy env. Prod: the reverse proxy must route
    `/ai/*` to :9001 with buffering off (`X-Accel-Buffering: no` is set too), and
    the Vercel build derives the relay from `VITE_POCKETBASE_URL`.

- Long AI requests go through `AiTasksProvider` (`app/ai/tasks.tsx`, mounted by
  `AiContext`): closing a sheet or changing pages no longer aborts them. Use
  `runTask({ key, group, cacheKey, title, run })` and let the store own the
  `AbortController`; never abort on unmount/close. Successful results are
  written to `cacheKey` and appear in the task center (bottom-left pill +
  sonner toast); `attend(group)` marks a task as watched while its page/panel
  is open so it does not double-notify. Panels that can close mid-flight must
  restore the task when they reopen: use `decideAiRestore` from
  `app/ai/restore.ts` (running task first, then local state → store result →
  cache) instead of hand-rolling the checks, so a finished result never
  becomes unreachable. System notifications are opt-in via
  `AiSettings.notify` and only fire while the page is hidden. This is
  client-side background: reloading or fully closing the app still stops
  in-flight requests, because the task store lives in memory.
- General chat (`app/chat/`, `/chat`): assistant-ui primitives +
  `useExternalStoreRuntime`; messages persist in `chat_messages` as content
  parts. A run loops up to 6 model rounds while it calls `sandbox_*` tools.
  The sandbox runs **Python or JavaScript on the server** in a Docker
  container (one image per language, selected by `sandbox_run.language`):
  read-only root, non-root user, all capabilities dropped, PID/memory/CPU
  limits, 20s wall clock, JSON on stdin (no code in argv), and the dedicated
  `mimi-sandbox` network whose egress firewall allows only public
  DNS/HTTP(S). It has no mounts, no host networking and no `pb_data` / env
  secrets. `pocketbase/sandbox/` owns the runner, Dockerfile and firewall.
  Dev (no Docker in WSL) uses a direct `python3`/`node` subprocess; that
  fallback is not isolated and must never be used in production. Don't add
  host mounts, `--network host`, a Docker socket, or secrets to the container
  without re-evaluating prompt injection against the AI key and `pb_data`.
  `ask_user` is client-side: it pauses the tool loop, shows the inline panel
  (text/choice/confirm/location), and resolves the tool result so the same
  run continues. Location only ever comes from `navigator.geolocation`, so
  the browser permission prompt is the consent boundary; never infer it from
  IP or the server.
- AI entry points: 聊天, 记账 (natural-language + receipt parse, monthly review,
  category backfill), 动态 composer captions, Home (daily line, 去年今天,
  问问我的基地), Study (wrong-answer overview, targeted drill, sprint plan),
  and the year report at `/report`. Data sent to the provider is only what the
  feature builds locally; nothing AI-related is written back to PocketBase
  except the user-confirmed expense rows/categories.
- Adding a page: create `app/routes/_protected/_main/<name>/index.tsx` with
  `createFileRoute("/_protected/_main/<name>/")`, let the dev server regenerate
  `routeTree.gen.ts`, then add a nav entry in `components/NavButtons/index.tsx`.
- Style with Tailwind + `components/ui` primitives + `cn()` from
  `lib/utils.ts`. There are no CSS modules; the nav uses lucide icons.
- `hover:` styles only reach devices that can hover
  (`future.hoverOnlyWhenSupported` in `tailwind.config.js`). A touch tap
  latches `:hover` until the next tap, so a hover-only affordance looks stuck
  on a phone; use `active:` or state classes for touch feedback.
- Theme tokens live in `globals.css` (`:root` + `.dark`). Prefer semantic
  classes (`bg-card`, `text-muted-foreground`, `border-border`, `shadow-soft`)
  over raw colors so both schemes keep working. `ThemeProvider` is in
  `lib/theme.tsx`; the nav toggle persists the choice under `mimi-theme`.
- Use `toastPromise` for async user actions (loading/success/error toasts).
- Overlays must close on the mobile back gesture (edge swipe / hardware back)
  instead of navigating the page behind them away. `lib/useBackDismiss.ts`
  provides this, and `Dialog`, `Sheet`, `Drawer` and `AiSheet` call it for you.
  Hand-rolled full-screen surfaces (e.g. `QuizRunner`) must call it themselves.
  It keeps one shared history entry while any overlay is open and unwinds
  nested overlays one at a time. `AiSheet` is a Radix dialog on purpose: a
  plain `div` over a `Drawer`/`Dialog` is "outside" for them, so tapping any
  button in the AI panel also closes the sheet underneath (e.g. the new-post
  composer vanishing when you pick a caption).
- The shell assumes `100dvh`; keep page scrolling inside the `_main` outlet.
- Accessibility: `globals.css` provides a global `:focus-visible` outline and
  disables decorative animation under `prefers-reduced-motion`. Don't add
  `outline-none` to interactive elements; keep icon-only controls labelled.
  `_main.tsx` ships a skip link to `#main-content`.

## Forked shadcn primitives

`components/ui/` is a **fork**, not pristine `shadcn add` output. Four files
carry customizations that must survive any future `shadcn add` / `init` /
primitives refresh:

- `dialog.tsx` — the `Dialog` root calls `useBackDismiss`; `DialogContent`
  adds `overlayClassName` and `showCloseButton`.
- `sheet.tsx` — the `Sheet` root calls `useBackDismiss`.
- `drawer.tsx` — the `Drawer` root calls `useBackDismiss` and defaults
  `repositionInputs={false}` (our own keyboard handling sizes the sheet).
- `sonner.tsx` — theme-aware `Toaster` driven by `useTheme()`.

`components.json` records the fork (see its `x-mimi-fork` note), and the ESLint
override in `eslint.config.js` now lint-checks `components/ui/`. **Do not
regenerate these files** with the shadcn CLI without re-applying the
customizations above (or moving them into `components/overlays/` wrappers and
re-pointing every importer). The customizations live inside the primitives
today because all app imports point at `@/components/ui/*`; a full wrapper
extraction would also require touching importers outside the UI layer.

Tailwind v4 note: upgrading Tailwind does **not** rewrite these `.tsx` files —
its real concerns are `darkMode: ["class"]` → `@custom-variant`,
`hsl(var(--x))` tokens → `@theme inline`, `@tailwind` →
`@import "tailwindcss"`, and `tailwindcss-animate`. v4 makes
`hoverOnlyWhenSupported` the default, so the mobile hover fix (and the
`active:` counterparts added to `buttonVariants`) stays valid.

## Gotchas

- Router context (`auth`, `queryClient`) is injected in `app/main.tsx`; add new
  root context keys in both the router and `__root.tsx`.
- Two typecheckers, both run in the pre-commit hook: `bun run typecheck`
  uses Bun's built-in `bun check` (bundled TypeScript, fast), while
  `bun run typecheck:tsc` runs the repo-pinned `typescript@^5.6.3`
  `tsc --noEmit`. Keep `"types": ["bun"]` and no `baseUrl` in
  `tsconfig.json`.
- Run `bun run setup:hooks` once per clone to enable `.githooks/pre-commit`,
  which runs `bun fmt --staged`, `bun check`, `bun run typecheck:tsc`,
  `bun run test`, `bun run lint`, and `bun run format:check`.
- `APP_VERSION` and `APP_SHA` are Vite `define` globals (declared in
  `vite-env.d.ts`), not environment variables. The app shows the build sha,
  not a version number: there is no release-bump step.
- `pb.autoCancellation(false)` in `lib/pb.ts` is intentional: the feed and like
  queries would otherwise abort each other.
- PocketBase records use `created` / `updated`; app types map them (e.g.
  `createdAt`).
- Build output is `build/` (not `dist`). `vercel.json` rewrites all paths to
  `/` for SPA routing. Vercel and the self-hosted PocketBase serve **two
  separate builds**: Vercel builds from the repo, while `deploy-spa.yml`
  builds with `VITE_POCKETBASE_URL=same-origin` and POSTs its own tarball to
  `/spa/publish`; PB serves that copy from `build/` via `--publicDir` in prod.
  Both hosts run at once.
- PWA: `public/sw.js` is hand-written with a `VERSION` constant; bump it when
  caching behavior changes. It is registered only in production builds by
  `lib/service-worker.ts`. New workers wait for `SKIP_WAITING`; the app shows a
  "有新版本可用" toast and reloads only after the user accepts. Navigation
  failures fall back to the cached shell, then to an inline offline page.
- `lib/env.ts` validates `VITE_POCKETBASE_URL` at module load — a missing env
  var crashes the app immediately.
- Default branch is `master`. Pushing `pocketbase/**` to `master` triggers
  `.github/workflows/deploy-db.yml` → `/db/sync` (git pull, stop PB, snapshot
  `pb_data` while it is down, restart; migrations apply on restart even with
  automigrate off).
  Frontend paths trigger `.github/workflows/deploy-spa.yml`, which builds with
  `VITE_POCKETBASE_URL=same-origin` and POSTs the tarball to `/spa/publish`;
  PB serves it from `build/` with no restart (`build.old` keeps one
  generation, `/spa/rollback` swaps back).
- `pocketbase/server.ts` must stay inside `pocketbase/`: the binary resolves
  `pb_migrations` and `pb_hooks` relative to the data dir.
- Never commit `.env`, `.env.prod`, `pocketbase/pb_data/`, or `tmp/`.

## Read before changing sensitive areas

- `pocketbase/README.md` — server, deploy endpoint, ops, secrets.
- `scripts/server-setup.sh` — fresh install / recovery.
- `.github/workflows/deploy-db.yml` — deploy trigger and retry behavior.
- `.github/workflows/deploy-spa.yml` and the `/spa/*` routes in
  `pocketbase/server.ts` — self-hosted frontend build and publish.
- `app/routes/_protected.tsx` and `lib/auth.tsx` — auth flow and redirects.
